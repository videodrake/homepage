# 리뷰 생성 시스템 — 인수인계 문서

Onroad(지구력코어) 제품에 들어갈 러너 가상 후기 **100개를 Claude API로 자동 생성**하는 도구.
다음 사람이 이어서 작업할 수 있도록 지금까지의 설계·시행착오·다음 단계를 정리했다.

---

## 1. 배경과 목적

- **용도**: `/shopinfo/runner-reviews.html`(그리고 필요 시 `/product/detail.html` 리뷰 탭)에 들어갈 러너 후기 콘텐츠를 채우기 위한 텍스트 생성기.
- **왜 자동 생성**: 초기 론칭 단계에서 실사용 후기가 축적되기 전 페이지 공백을 메우기 위한 **시드 데이터**.
- **출력 형태**: 구조화된 JSON 배열(러너 프로필 + 본문). 홈페이지 삽입은 이 문서 범위 밖(후가공 단계).
- **타깃 독자(가상 작성자)**: 한국 30~40대 남성 러너.

### ⚠ 법적·윤리적 주의
이 리뷰들이 **실제 상용 페이지의 "구매 후기" 섹션**에 아무 라벨 없이 올라가면 한국 표시·광고법상
**기만적 광고**로 걸릴 위험이 있다. 반드시 다음 중 하나로 대응할 것:

- "브랜드가 구성한 가상 시나리오" 같은 라벨 명시
- 실제 모니터링단 후기로 대체
- 디자인 시안·포트폴리오 용도로만 사용하고 상용 페이지에서 제외

## 2. 폴더 구조

```
tools/generate-reviews/
├── HANDOFF.md            ← 이 문서
├── package.json          ← @anthropic-ai/sdk + dotenv
├── .gitignore            ← node_modules, .env, samples/, output/
├── .env                  ← ANTHROPIC_API_KEY (커밋 금지)
├── generate.js           ← 메인 스크립트 (CLI)
├── profiles.js           ← 러너 프로필 생성기 (seeded PRNG)
├── prompts/
│   ├── _shared.md        ← 모든 프롬프트가 앞에 붙이는 공통 가이드
│   ├── v1-skeptic.md     ← 회의적 → 조심스러운 긍정
│   ├── v2-observer.md    ← 수치·관찰 + 주관 체감
│   ├── v3-routine.md     ← 복용 루틴·습관화 중심
│   ├── v4-terse.md       ← 단문·담백
│   ├── v5-scene.md       ← 특정 훈련/대회 장면부터 시작
│   └── v6-comparison.md  ← 이전 보충제와 비교부터 시작
├── samples/              ← npm run sample 결과 (각 프롬프트당 5개)
└── output/               ← npm run full 결과 (최종 100개)
```

## 3. 환경 세팅

```bash
cd tools/generate-reviews
npm install
echo "ANTHROPIC_API_KEY=sk-ant-..." > .env
```

`.env`는 gitignore 되어 있음. 이미 있는 로컬 키가 있다면 재사용.

## 4. 실행 방법

### 샘플 테스트 (프롬프트 비교용)
```bash
npm run sample                               # 6개 프롬프트 × 5개 = 30개, Haiku 4.5
npm run sample -- --model=claude-sonnet-4-6  # Sonnet으로 돌리기
npm run sample -- --prompt=v1-skeptic        # 특정 프롬프트만
```
결과는 `samples/<prompt>.json` 에 저장.

### 최종 100개
```bash
npm run full -- --prompt=v1-skeptic          # 단일 프롬프트로 100개
# 또는 분포 섞어서 여러 번 돌린 뒤 output/ 에서 병합 (분포 모드는 아직 미구현 — §8 참고)
```

### 주요 CLI 플래그
| 플래그 | 기본값 | 설명 |
|---|---|---|
| `--mode` | `sample` | `sample` 또는 `full` |
| `--count` | sample=5, full=100 | 생성 개수 |
| `--prompt` | (sample은 전체 순회) | 사용할 프롬프트 이름 |
| `--model` | sample=Haiku, full=Sonnet | `claude-haiku-4-5-20251001` / `claude-sonnet-4-6` / `claude-opus-4-7` |
| `--seed` | 42 | 프로필 PRNG 시드 (동일 시드 = 동일 프로필) |
| `--concurrency` | 2 | API 병렬 호출 수 |

## 5. 러너 프로필 생성 (`profiles.js`)

LLM이 프로필까지 상상하게 두면 편차가 심해서 **프로필은 스크립트가 결정론적으로 생성**하고 LLM은 본문만 쓰게 분리했다.

### 분포 (100명 기준, weight 기반)
| 필드 | 버킷 | 비중 |
|---|---|---|
| 거리 | 하프 25 / 10K 23 / 풀코스 22 / 울트라 13 / 5K 12 / 트레일 5 | 러닝 인구 분포 근사 |
| 연령 | 30대 초반 25 / 중반 30 / 후반 22 / 40대 초반 15 / 중반 8 | 30대 중반 정점 |
| 연차 | 1-2년 12 / 3년 18 / 4-5년 28 / 6-8년 25 / 10년+ 17 | 중상급 편중 |
| 섭취일수 | 22·25·30(×3)·45(×2)·60(×2)·75·90 | 30일이 가장 흔함 |
| 별점 | 5점 78% / 4점 22% | |
| 주행거리 | 거리 버킷별 범위 내 랜덤 | ex. 풀코스 55~95km |

### 파생 필드
- `concern` — 거리 버킷별 고민 풀에서 매칭(10K 러너에게 "30km 이후…" 같은 부조화 방지).
- `closing_style` — **마무리 분포를 스크립트가 통제**. 그대로 두면 LLM이 재구매 얘기로만 닫음.
  - repurchase 18 / next_race 18 / product_detail 12 / price_question 10 / with_other 10 / crew 8 / observation 10 / aside 8 / next_check 6
- `closing_hint` — 해당 스타일의 지시문 그대로 프롬프트에 주입됨.

### seeded PRNG
`mulberry32` 사용. 같은 `--seed` → 같은 프로필 세트. 디버깅·재현에 필수.

## 6. 프롬프트 설계

### 레이어 구조
1. `_shared.md` — **공통 규칙** (금지어·톤·분량 일반론·헤지 뱅크·마무리 규칙)
2. `vN-*.md` — **각 앵글별 고유 지시** (도입 방식·흐름·해당 앵글 예시 2~3개)
3. 프로필 JSON — 런타임에 `{{PROFILE_JSON}}` 자리에 주입

`generate.js` 의 `loadPrompt()` 가 자동으로 `_shared.md` 를 프롬프트 앞에 붙인다.

### 공통 규칙 요약 (자세한 건 `_shared.md` 참조)
- 과장 금지 ("대박", "진짜 효과", "인생템")
- 부정 금지 ("효과 없어요", "극적인 변화는 없지만", "재구매 안 할")
- 이모티콘·감탄사·영어 혼용·한자 혼용 금지
- 자기소개로 첫 문장 시작 금지
- 프로필 필드 나열 금지 (2~3개만 녹여라)
- 헤지 표현 한 리뷰에 최대 1번
- **금지 헤지** (과반복 이력): "며칠 반복되니 우연은 아닌", "비교군이 없어서 확신은 못 하겠지만"
- 마무리는 `closing_hint` 반드시 따를 것

### 프롬프트별 차별점
| 이름 | 도입 앵글 | 톤 특징 | 분량 |
|---|---|---|---|
| v1-skeptic | 고민·회의부터 | 이전 시도 → 조심스러운 긍정 | 180~300자 |
| v2-observer | 특정 수치·구간부터 | 기록·심박·케이던스 + 주관 체감 | 220~330자 |
| v3-routine | 복용 시점·상황부터 | 습관화·편의성 중심, 부정어 일절 금지 | 180~290자 |
| v4-terse | 짧은 팩트 1줄 | 마침표 단문, 수식어 최소 | 90~170자 |
| v5-scene | 특정 장면(오늘/어제 훈련)부터 | 현장감·일기체 | 200~320자 |
| v6-comparison | 과거 보충제·방법과의 비교부터 | "이전 vs 지금" | 210~320자 |

## 7. 반복 표현 이슈 & 대응 이력

생성 과정에서 **같은 문구가 전체 리뷰에 과반복되는 현상**이 반복적으로 발견됨. 대응:

| 반복 표현 | 빈도 (30개 중) | 대응 |
|---|---|---|
| "플라시보일 수도 있지만" | 12개 (1차) | _shared.md 헤지 뱅크에서 강등 ("가끔만 사용") |
| "며칠 반복되니 우연은 아닌 것 같다" | 15개 (2차) | **완전 금지어로 박음** |
| "비교군이 없어서 확신은 못 하겠지만" | 10개 (3차) | **완전 금지어로 박음** |
| "한 통 더 시켰다" 마무리 | 15개 (2차) | `closing_style` 필드로 스크립트 통제 |
| "알갱이 작고 냄새가 없어서" | 여러 리뷰 | v3에만 국한되도록 가이드 조정 |
| "劇적인" 같은 한자 혼용 | 2건 | _shared.md에 한자 금지 명시 |
| "dramatic한" 같은 영어 혼용 | 2~3건 | _shared.md에 영어 혼용 금지 명시 |
| "재구매는 안 할" 같은 부정 마무리 | 1건 (1차 Haiku) | Sonnet 전환 후 사라짐 |

**교훈**: LLM은 뱅크에서 **안전한 표현 1~2개만 반복 선택**하는 경향이 강함. 뱅크 아이템을
"가능"으로 제시하면 몇 개만 과사용되니, 문제가 된 표현은 **완전 금지**로 박고 뱅크 자체를
꾸준히 갱신해야 함.

## 8. 모델·비용 계산

샘플 실측 기반:

| 모델 | 샘플 30개 | 전체 100개 | 비고 |
|---|---|---|---|
| Haiku 4.5 (`claude-haiku-4-5-20251001`) | ~$0.10 | ~$0.30 | 반복 패턴이 많은 편 |
| Sonnet 4.6 (`claude-sonnet-4-6`) | ~$0.33 | ~$1.1~1.8 | 현재 기본값, 품질 최적 |
| Opus 4.7 (`claude-opus-4-7`) | ~$1.7 | ~$5~6 | 미테스트 |

**Rate limit**: Sonnet 기본 티어 `30,000 input tokens/min`. 현재 프롬프트(_shared 포함) ≈ 3K input tokens × concurrency 2 → 100개 생성에 약 15분 소요 예상. `generate.js` 에 지수 백오프 retry(429/529/5xx, 최대 6회) 내장.

## 9. 작업 이력 타임라인

1. **1차 (Haiku)** — 프롬프트 4개(v1-skeptic, v2-observer, v3-routine, v4-terse). "플라시보" 반복·자기소개 첫 문장 문제 발견.
2. **2차 (Haiku)** — `_shared.md` 도입, 프롬프트 6개로 확장, 자기소개 금지 명시. "며칠 반복되니 우연은 아닌" 새 반복 등장.
3. **3차 (Sonnet)** — 품질 대폭 개선. 남은 문제: 두 헤지 표현 과반복 + 한자 혼용 + rate limit 에러.
4. **4차 (Sonnet)** — 문제 헤지 완전 금지, `closing_style` 스크립트 통제, 한자 금지, retry 추가.
5. **커뮤니티 조사 (진행 중)** — 디시 러닝갤·클리앙·브런치·뽐뿌·GQ 등 30+개 실제 러너 글 분석. 다음 단계에서 프롬프트 전면 재작성 예정.

## 10. 남은 작업 (다음 사람이 이어서)

### A. 프롬프트 전면 리라이트 (핵심)
커뮤니티 조사 결과를 반영해야 함. 주요 업데이트 포인트:

- **페이스 표기 형식 교체**: "4:35/km" → "430 페이스" (3~4자리 숫자 붙여 쓰기)
- **실 어휘 뱅크 주입**: "조지다", "찍다", "뚫다", "넣다", "퍼지다", "런린이", "대회뽕", "서브3/4", "싱글", "sub 2", "페메", "마일리지"
- **보충제 후기 3박자 공식** (실 러너 글에서 일관 관찰):
  1. 조건부 효과 (ex. "30km 넘어갈 때만 느낌 옴")
  2. 의심 한 줄 필수 ("근데 이게 진짜 그거 때문인지 모르겠다")
  3. 맛·가격 불평 또는 일상 곁가지
- **감정 = 신체 묘사로**: "힘들었다" ❌ / "다리가 안 들어져요", "토할 것 같아", "쥐가 날 것 같은" ✅
- **자기비하 유머 허용**: "나 따위가", "월 300 찍는 조빱인데"
- **결론 열림/반성형 마무리 옵션**: "다음에 또 부상 오면 무조건 쉰다" 같은 톤
- **맥락 점프·숫자 나열·문법 깨짐 허용**: "뛰고옴", "조졌음", "7월 240km, 8월 430km"

상세 조사 결과는 대화 로그 / 조사 에이전트 보고서 참조. 참고 소스 30+개가 보고서에 URL 인용되어 있음.

### B. 분포 모드 (선택)
현재 `generate.js` 는 하나의 프롬프트로만 돌아감. 다양성을 위해 100개를 프롬프트별 비율로 섞고 싶으면
`--mode=full` 에 `--distribution='{"v1-skeptic":22,"v4-terse":18,...}'` 같은 옵션 추가 고려.
제안 분배:

- v1-skeptic: 22 (톤 기준점)
- v4-terse: 18 (짧은 글로 다양성 기여)
- v5-scene: 17 (현장감)
- v2-observer: 15
- v3-routine: 15
- v6-comparison: 13

### C. 품질 검수 루프 (선택)
생성 후 반복 표현 자동 카운트 스크립트를 만들어 임계치 이상이면 재생성하는 QA 단계 고려.
지금은 수동 체크.

### D. 홈페이지 삽입 포맷 변환
`output/reviews-*.json` → `runner-reviews.html` 카드 HTML로 변환하는 소규모 스크립트 필요.
`rn-card` 구조에 맞춰 프로필 필드 매핑. 이 도구 외부 작업.

## 11. 파일 변경 시 주의사항

- `_shared.md` 수정 → 6개 프롬프트 전부에 영향. 작은 수정도 반드시 샘플 먼저.
- `profiles.js` 의 weight 배열 변경 → 프로필 분포 달라짐. seed 고정이므로 같은 seed+같은 weight 면 동일 결과.
- `generate.js` 의 `loadPrompt()` → `_shared.md` 와 `_` 로 시작하는 모든 파일을 자동 제외(프롬프트 목록에서 빠짐). 새 공통 파일 만들 때 `_` 접두사 쓰면 자동 관리됨.
- 프롬프트 파일에 frontmatter(`---`로 감싼 YAML) 허용. 현재는 메타 기록용이며 파싱은 안 됨.

---

## 12. 알려진 한계

- **같은 seed 내에서 다양성 유한**: seed=42 로 100명을 뽑으면 거리·연령·연차 조합이 어느 정도 반복됨. 필요하면 `--seed` 를 바꿔 다른 배치 생성.
- **러너 용어 깊이는 LLM 훈련 데이터에 의존**: 드문 은어("네가", "BK", "하뛰하쉬")는 프롬프트에 명시적으로 넣어야 재현됨.
- **Haiku에서 구조 반복 더 심함**: 비용 차이가 크지 않으면 Sonnet 권장.
- **출력 검증 없음**: LLM이 가끔 "여기 리뷰 본문입니다:" 같은 서두를 붙임. 샘플 확인 후 필요시 후처리 규칙 추가.
