# 콘텐츠 발행 로그

> Git 기준 발행 로그 원본. Claude Project가 GitHub/Git 저장소를 읽을 수 있으면 Project Knowledge의 로그가 아니라 이 파일을 기준으로 내부링크와 다음 주제를 판단한다.

---

## 1. 운영 원칙

- 이 파일은 Git에 커밋되는 최신 원본이다.
- Project Knowledge의 `콘텐츠_발행_로그.md`는 Git 접근이 안 될 때 쓰는 백업본이다.
- Git 로그와 Project Knowledge 로그가 다르면 이 파일을 우선한다.
- 최종 자사몰 배포가 끝나면 Claude Code 자리 3이 이 파일을 갱신해야 한다.
- 네이버/인스타 수동 발행 후에는 사용자가 이 파일을 갱신하고 Git에 반영한다.

## 5. 갱신 책임

### Claude Project

- 새 원고를 만들 때 이 파일을 읽고 중복을 피한다.
- 직접 이 파일을 수정하지 않는다.

### Codex 자리 2

Codex PR을 만들 때 `content/CONTENT_STATE.md`를 갱신한다.

- draft 검토 후 처리 시작: `codex_processing`
- published 생성 후 PR 병합: `published_md_ready`

### Claude Code 자리 3

자사몰 배포가 성공하면 같은 PR에 아래를 반영한다.

- `content/CONTENT_STATE.md`: 해당 slug를 `deployed`로 변경
- `content/CONTENT_LOG.md`: 발행 로그 한 줄 추가 또는 기존 예정 항목 완료 처리
- 자매 클러스터 매핑의 Journal 항목 상태를 `완료`로 변경

### 사용자

네이버 블로그나 인스타그램을 수동 발행한 뒤 이 파일의 해당 항목을 갱신한다.

## 6. AI 브리핑 노출 추적

발행 약 4주 후 수기로 측정한다.

1. Primary 키워드로 네이버 검색
2. AI 브리핑 박스 노출 여부 확인
3. 우리 글이 인용 출처로 표시되는지 확인
4. 관련 질문 박스에 등장하는지 확인
5. 일반 검색 1페이지 내 노출 여부 확인

기록값:

- 노출
- 부분 노출
- 미노출
- 미측정
