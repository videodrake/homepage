# 자리 1 자가 검증 가이드

> Claude(자리 1)가 글을 완성한 후, 자리 2로 넘기기 전에 결정적 검증을 수행하는 방법.
> 5중 체크리스트의 27항목 중 기계가 검증 가능한 부분을 자동화.
> v1 (2026-05-12).

---

## 1. 왜 자가 검증인가

기존 5중 체크리스트(`mode_journal.md` §9, `mode_tofu.md` §10)는 **Claude의 자가 점검**이다. 27항목 중:

- **자동 검증 가능 (8~10항목)**: 마커-명세 동기화, 5대 금지어, 의약품 오인 용어, 필수 필드 누락, 면책 문구 마커, 푸터 안내 문장 → 정규식으로 확인
- **판단 필요 (나머지)**: 흡입력, 톤, AEO 품질, 감정 톤 일관성, 정보갭 위치 등 → Claude 자가 점검 유지

자동 검증 가능한 8~10항목을 **사람 같은 자가 점검에 맡기면** 다음 사고가 발생할 수 있다:

| 사고 유형 | 발생 방식 |
|---|---|
| 마커 형식 변형 | "[IMG_1]" 같은 변형을 Claude가 "비슷한 형식이니 OK"라고 자가 판단 |
| 5대 금지어 누락 | 글 길이가 길면 1~2회 등장한 "피로" 같은 단어를 못 보고 넘김 |
| 식별명 미세 차이 | "도입부 헤더" 본문 vs "도입부 사진" 명세 — 사람 눈에는 비슷해 보임 |
| 필수 필드 누락 | "alt 텍스트"는 적었는데 "비율"을 까먹는 등 |

이런 사고는 **결정적 검증으로 0%로 만들 수 있다.** Claude가 자기 글에 대해 자가 점검하는 대신, 결정적 도구의 출력을 보고 수정하는 방식.

---

## 2. 검증 도구 두 가지

### 2-1. `parse_boxes.py` — 자리 1 출력 사양 검증

다음 항목 자동 검사:
- 마커-명세 매칭 (1:1, 식별명 일치)
- 마커 형식 변형 감지 (5가지 변형 패턴)
- 필수 필드 누락 (종류·비율·alt 텍스트·프롬프트)
- 명세 헤더 형식

### 2-2. `regulation_check.py` — 규제 6항목 검증

다음 항목 자동 검사:
- "지구력코어" 0회
- "옥타코사놀" 0회
- 5대 금지어 0회
- 의약품 오인 용어 0회
- 푸터 안내 문장 0건
- 면책 문구 존재

## 3. 자가 검증 실행 방법

### 3-1. Claude가 직접 실행 가능한 환경

Claude가 컴퓨터 도구(bash 등)를 사용할 수 있는 환경이라면:

```bash
# 1. 출력 사양 검증
python tools/parse_boxes.py content/draft/journal-01-a.md
# exit 0: 사양 통과
# exit 1: 위반 — 출력 리포트 확인 후 수정

# 2. 규제 검증
python tools/regulation_check.py content/draft/journal-01-a.md
# exit 0: 규제 통과
# exit 1: 위반 — 출력 리포트 확인 후 수정
```

두 검사 모두 exit 0이면 자리 2에 넘길 수 있는 상태.

### 3-2. Claude가 도구를 직접 실행할 수 없는 환경

Claude Project 안에서 글을 쓰는 경우, 검증 도구를 직접 실행할 수 없다. 이 경우:

1. 글 작성 완료 후, 자리1_출력사양.md §10의 **빠른 검증 체크리스트**를 사용자에게 보여주고 사용자가 점검하도록 안내
2. 사용자가 검증 도구를 로컬에서 돌릴 수 있도록 명령어 예시 제공

이 가이드는 환경 3-1을 가정한 상세 흐름을 정의한다. 환경 3-2에서는 §6의 자가 점검 체크리스트만 활용.

## 4. 검증 흐름

### Phase 1 — 작성 완료 직후

```
1. 글의 본문 + 명세 섹션 작성 완료
2. python tools/parse_boxes.py <파일> 실행
3. exit 1이면 출력 리포트의 위반 항목 확인
4. 위반 수정 후 다시 실행 → exit 0까지 반복
```

### Phase 2 — 형식 검증 통과 후

```
1. python tools/regulation_check.py <파일> 실행
2. exit 1이면 위반 항목 확인
3. 위반 수정 후 다시 실행 → exit 0까지 반복
```

### Phase 3 — 두 검증 모두 통과 후

```
1. 사용자에게 글 출력
2. "두 자동 검증 모두 통과. 자리 2에 넘길 수 있는 상태입니다." 보고
```

## 5. 위반 시 수정 가이드

### 5-1. `parse_boxes.py` 위반 — 흔한 5가지

#### A. "명세 누락 마커"

```
명세 누락 마커: IMG-[3]
```

본문에는 IMG-3 마커가 있는데 명세 섹션에 IMG-3가 없음.

수정: 명세 섹션에 `### IMG-3 — 식별명` 추가.

#### B. "마커 없는 명세"

```
마커 없는 명세: IMG-[3]
```

명세 섹션에는 IMG-3가 있는데 본문에 마커 없음.

수정: 본문에 `[IMG-3: 식별명]` 마커를 적절한 위치에 추가. 또는 명세 섹션에서 IMG-3 제거.

#### C. "식별명 불일치"

```
IMG-1 식별명 불일치:
  마커: 도입부 헤더
  명세: 도입부 사진
```

수정: 마커와 명세의 식별명을 글자까지 동일하게 맞춤.

#### D. "의심 마커 N개 발견"

```
⚠️ 의심 마커 5개 발견:
  line 11: [IMG-2 콜론없음]
            → 콜론 ':' 누락 (정상: '[IMG-N: 식별명]')
```

수정: 출력에 표시된 정상 형식으로 마커 수정.

#### E. "필수 필드 누락 명세 N개"

```
⚠️ 필수 필드 누락 명세 3개:
  IMG-1 (...): alt 텍스트 누락
  IMG-2 (...): 프롬프트 누락
  IMG-3 (...): 비율 누락
```

수정: 해당 명세에 누락 필드 추가.

### 5-2. `regulation_check.py` 위반 — 흔한 6가지

#### A. 5대 금지어

```
❌ 5대 금지어 (§6-2 옥타코사놀 5대 금지어)
   단어: '피로'
     line 5: 마라톤 후반에 피로가 쌓이면...
```

수정: 5대 금지어를 다른 표현으로 교체. 예시:
- "피로" → "근육 부담", "에너지 고갈", "회복 필요"
- "스테미너" → "지속력", "에너지 비축"
- "파워" → "출력", "추진력"

#### B. 의약품 오인 용어

```
❌ 의약품 오인 용어 (§6-3)
   단어: '효능'
```

수정: 표준 대체어 사용:
- 복용 → 섭취
- 효능 → 기능
- 임상시험 → 인체적용시험
- 처방 → 배합
- 알약 → 정제·캡슐

#### C. "효과" WARN

```
⚠️ "효과" 단독 사용 (문맥 검토 필요)
   line 11: ## 효능과 효과
```

WARN은 즉시 차단은 아니지만, 문맥상 의약품 오인 가능성이 있는지 검토.
- 합성어("효과적인", "효과적으로")는 자동으로 화이트리스트 통과
- 단독 사용 "효과"는 가능하면 "도움" "결과" "변화" 등으로 교체

#### D. 푸터 안내 문장

```
❌ 푸터 안내 문장 (§6-5)
   단어: '하단'
     line 17: 자세한 정보는 하단 버튼을...
```

수정: 본문에서 푸터를 가리키는 문장 전체 제거. Journal 본문은 §6-5 합법 우회 구조 — 푸터를 본문에서 직접 언급하지 않는다.

#### E. 면책 문구 누락

```
❌ 면책 문구 누락 (§6-5)
```

수정: 본문 종료 직후 다음 표준 면책 문구 추가:

```
※ 본 정보는 제품정보와 관련 없는 내용이며, 학술 자료에 근거한 일반 건강정보입니다.
※ 의학적 진단을 대체하지 않습니다.
```

#### F. 제품명·성분명

```
❌ 제품명 직접 언급
   단어: '지구력코어'
```

수정: Journal 본문에서 제품명·성분명 0회 룰을 위반. 해당 문장을 일반적 표현으로 교체.
- "지구력코어" → 제품명 전체 제거
- "옥타코사놀" → "특정 식품 성분", "관련 영양 보조 성분"

## 6. 환경 3-2용 — 사용자 안내 텍스트 템플릿

Claude가 도구를 직접 실행할 수 없는 환경에서, 글 작성 완료 시 다음 메시지로 사용자 안내:

```
글 작성을 완료했습니다. 자리 2(Codex)에 넘기기 전 다음 두 검증을 권장합니다:

1. 출력 사양 검증 (마커, 명세, 필수 필드)
   $ python tools/parse_boxes.py content/draft/journal-01-a.md

2. 규제 검증 (5대 금지어, 푸터 안내, 면책 문구)
   $ python tools/regulation_check.py content/draft/journal-01-a.md

두 검증이 모두 exit 0을 반환하면 자리 2에 넘길 수 있는 상태입니다.
직접 실행이 어려우면 자리1_출력사양.md §10 빠른 검증 체크리스트로 시각 검토하세요.
```

## 7. 자가 검증과 5중 체크리스트의 관계

기존 5중 체크리스트는 그대로 유지한다. 이 가이드는 그 위에 **자동 검증 레이어를 한 겹 추가**하는 것이다.

| 체크리스트 항목 | 검증 방법 |
|---|---|
| 규제 5항목 (5대 금지어 등) | `regulation_check.py` 자동 |
| 마커-명세 동기화 | `parse_boxes.py` 자동 |
| 필수 필드 누락 | `parse_boxes.py` 자동 |
| 흡입력 7~8항목 | Claude 자가 점검 |
| AEO 3~5항목 | Claude 자가 점검 |
| 구조 4항목 | Claude 자가 점검 |
| 내부링크 3항목 | Claude 자가 점검 |
| 톤·AI 톤 금지선 | Claude 자가 점검 |

자동 검증은 "기계가 잡을 수 있는 것"만 가져가고, Claude의 자가 점검은 "기계가 잡을 수 없는 것"에 집중하게 만든다. 둘 다 필요하다.
