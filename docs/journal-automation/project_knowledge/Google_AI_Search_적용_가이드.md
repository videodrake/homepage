# Google AI Search 적용 가이드

> 기준 문서: Google Search Central, "Optimizing your website for generative AI features on Google Search" (Last updated 2026-05-15 UTC).
> 목적: 자사몰 Journal과 네이버 파생 원고가 AI 검색을 의식하되, 억지 AEO/GEO 해킹으로 흐르지 않게 한다.

## 1. 핵심 관점

Google은 생성형 AI 검색을 별도 해킹 대상으로 보지 않는다. AI Overviews와 AI Mode는 검색 인덱스와 기존 랭킹/품질 시스템을 바탕으로 작동한다. 따라서 이 프로젝트의 기본 원칙은 다음이다.

- AEO/GEO는 별도 문법이 아니라 좋은 SEO의 일부로 본다.
- 검색엔진보다 실제 독자가 만족하는 글을 우선한다.
- 질문 변형을 많이 만들기보다, 한 글이 하나의 문제를 깊게 해결하게 한다.
- AI가 쉽게 재조합할 수 있는 평범한 요약문보다, 지구력코어가 축적한 관점과 한국 러너 맥락을 넣는다.

## 2. 콘텐츠 작성 원칙

### 2-1. 비상품성 콘텐츠

다음 글은 피한다.

- "마라톤 후반 페이스 관리 7가지 팁"처럼 어디서나 나올 수 있는 목록형 글
- 검색어 변형만 바꾼 유사 글
- AI가 이미 흔하게 말하는 일반론 요약
- 출처 없는 "연구에 따르면"과 일반 조언의 조합

대신 다음을 넣는다.

- 한국 30~40대 러너가 실제로 겪는 장면
- 숫자, 조건, 개인차, 한계
- 한 시리즈 안에서 누적되는 관점
- 네이버/자사몰/인스타로 분기되더라도 같은 중심 주장

### 2-2. Query Fan-Out 대응

생성형 검색은 원 질문에서 여러 관련 질문을 동시에 펼쳐 본다. 이를 억지로 페이지 수로 대응하지 않는다.

한 Journal 안에서 다음을 자연스럽게 포함한다.

- 핵심 질문 1개
- 보조 질문 2~4개
- 비교표 또는 숫자 요약 1개 이상
- FAQ 3~5개
- 이미지 alt 텍스트와 캡션의 설명성

단, 관련 질문마다 별도 글을 만들거나, H2/FAQ를 검색어 변형으로만 채우지 않는다.

### 2-3. 사람 중심 만족도

최종 출력 전 다음 질문에 답한다.

- 독자가 이 글을 읽고 다시 검색하지 않아도 핵심 답을 얻는가?
- 같은 주제를 다룬 흔한 글보다 한 단계 더 구체적인가?
- 제품명 없이도 자사몰 Journal에 남길 만한 신뢰 자산인가?
- 글의 구조가 사람에게 읽기 쉬운가, 아니면 검색 노출을 위한 항목 나열인가?

## 3. 기술 구조 원칙

자사몰 Journal HTML은 다음을 유지한다.

- 크롤 가능한 정적 HTML 본문
- 명확한 `h1`, `h2`, `h3` 구조
- 본문과 일치하는 이미지 alt 텍스트
- 고품질 이미지 파일
- 모바일에서 읽기 쉬운 페이지 경험
- 중복 URL을 만들지 않는 slug 관리
- 가능한 경우 `BlogPosting` JSON-LD 구조화 데이터

구조화 데이터는 AI 검색 노출을 보장하지 않는다. 단, 일반 검색의 명확한 이해를 돕는 보조 장치로 유지한다.

## 4. 하지 않을 것

- `llms.txt` 같은 별도 AI 전용 파일을 만들지 않는다.
- AI가 읽기 쉽다는 이유로 본문을 잘게 쪼개는 데 집착하지 않는다.
- 같은 주제를 검색어 변형별로 대량 생성하지 않는다.
- AI 검색 노출만을 위한 가짜 외부 언급, 후기, 인용을 만들지 않는다.
- 본문에 없는 FAQ나 구조화 데이터를 만들지 않는다.

## 5. 운영 체크리스트

- [ ] 원고가 검색어 변형이 아니라 독자 문제 하나에서 출발한다.
- [ ] 제목, H2, FAQ는 과장 없이 실제 질문에 답한다.
- [ ] 흔한 요약이 아니라 숫자/맥락/한계/실행 관찰점을 담았다.
- [ ] 이미지가 본문 이해를 돕고 alt 텍스트가 실제 이미지를 설명한다.
- [ ] 자사몰 변환 후 HTML은 `h1`/`h2`/`article` 구조를 유지한다.
- [ ] 구조화 데이터가 있다면 본문에 보이는 정보와 일치한다.
- [ ] 비슷한 쿼리 대응을 위해 중복 글을 만들지 않았다.
