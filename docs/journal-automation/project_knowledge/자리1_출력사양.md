## 1. 이 문서를 왜 따라야 하는가

자리 2의 파서는 **결정적 정규식**으로 작동한다. Claude가 본인 판단으로 형식을 미세하게 변형하면 (예: `[IMG_1]` `[이미지 1]`) 파서가 그 마커를 **묵묵히 누락**시키거나, 의심 마커로 검출해 워크플로우를 중단시킨다.

이 사양은 **Claude의 자유도를 제한하기 위한 것이 아니라**, 자유도를 가질 자리(글의 내용·톤·구조)와 가지면 안 될 자리(기계가 읽는 메타데이터)를 명확히 나누기 위한 것이다.

## 2. 파일명 규칙

### 2-1. 형식

```
journal-<NN>-<A|B>.md
```

- `<NN>`: Journal 번호. 두 자리 0 패딩 (`01`, `02`, ..., `99`)
- `<A|B>`: 시리즈 분할. 소문자
- **소문자만 사용**
- **하이픈만 사용** (언더스코어 `_`, 공백, 한글 금지)

### 2-2. 좋은 예 / 나쁜 예

```
✅ journal-01-a.md
✅ journal-02-b.md
✅ journal-10-a.md

❌ Journal_01-A.md          (대문자 + 언더스코어)
❌ journal-1-a.md           (0 패딩 누락)
❌ journal-01-A.md          (대문자 시리즈)
❌ 2026-05-12-journal-01-a.md (날짜 prefix — slug 추출 깨짐)
❌ 마라톤페이스유지.md       (한글 + 의미 없는 명명)
```

### 2-3. 파일명이 발행 URL까지 따라간다

`journal-01-a.md` → slug `journal-01-a` → `assets/journal-01-a/` → 자사몰 URL `/journal/journal-01-a`.

즉 파일명 한 글자가 바뀌면 자사몰 사이트의 URL도 바뀐다. 검색엔진이 새 URL을 다시 인덱싱해야 하고, 기존 내부링크가 깨진다.

**규칙**: 파일명은 한 번 정하면 끝까지 유지. 글 내용을 수정해도 파일명은 절대 바꾸지 않는다.

## 3. 본문 마커 사양

### 3-1. 정확한 형식

```
[IMG-<N>: <식별명>]
```

- `IMG-` 접두어 (대문자 + 하이픈, 다른 변형 불가)
- `<N>` 정수 (1부터 순차, 글 안에서 중복 없음)
- `:` 콜론 + 공백 1칸
- `<식별명>` 5~10자 한글 또는 영문 (괄호·특수문자 가능)
- `]` 닫는 대괄호
- **단독 줄**이어야 함 (다른 텍스트와 같은 줄에 두지 않음)

### 3-2. 좋은 예 / 나쁜 예

```
✅ [IMG-1: 도입부 헤더]
✅ [IMG-2: 글리코겐 곡선]
✅ [IMG-10: OUTRO 회수 장면]

❌ [IMG1: 헤더]                (하이픈 누락)
❌ [IMG_1: 헤더]                (언더스코어)
❌ [img-1: 헤더]                (소문자)
❌ [이미지 1: 헤더]             (한글 접두어)
❌ [IMG-1: 헤더 사진]           (식별명에 "사진" — 너무 길지 않으나 SEO 스팸 신호)
❌ [IMG-: 식별명]               (번호 누락)
❌ 본문 끝에 [IMG-1: 헤더] 다음 문장. (인라인 — 단독 줄 아님)
```

자리 2 파서는 위 5가지 변형 패턴을 **의심 마커로 감지**하고 워크플로우를 중단시킨다. Claude가 작성 직후 자가 검증할 때 이 패턴들을 명시적으로 피해야 한다.

### 3-3. 마커 번호 규칙

- 1부터 시작, 빠짐없이 순차 (1, 2, 3, ... — 1, 3, 5 같은 건너뜀 금지)
- 본문 등장 순서대로 번호 매기기 (제목 직후 = IMG-1)
- 한 글 안에서 같은 번호 중복 금지
- 식별명은 같은 글 안에서 유일해야 함 (예: "분위기 사진"이 두 개 있으면 "도입부 분위기 사진" / "OUTRO 분위기 사진"으로 구분)

## 4. 이미지 명세 섹션 사양

### 4-1. 섹션 시작

본문 종료(면책 문구 + 참고문헌 다음) 후, 다음 헤더로 섹션 시작:

```markdown
---

## 이미지 명세
```

- `---` 수평선으로 본문과 시각 분리
- `## 이미지 명세` 정확히 이 문구 (h2 레벨)

### 4-2. 각 명세 헤더

```markdown
### IMG-<N> — <식별명>
```

- `### IMG-` h3 레벨
- `<N>` 정수, 본문 마커와 정확히 일치
- ` — ` (공백 + em dash U+2014 + 공백)
  - 일반 하이픈 `-` 또는 en dash `–`도 자리 2 파서가 허용하지만, em dash `—`가 표준
- `<식별명>` 본문 마커의 식별명과 정확히 일치

### 4-3. 메타필드 — 필수/선택 분리

각 명세 헤더 직후 다음 형식으로 메타필드 나열:

```markdown
- **<키>**: <값>
```

#### 4-3-1. 필수 필드 (4개) — 누락 시 자리 2 거부

| 키 | 값 형식 | 예시 |
|---|---|---|
| `종류` | 자유 텍스트 | `분위기 사진` |
| `비율` | `숫자:숫자` (반드시 포함) | `21:9` 또는 `21:9 (와이드 시네마틱)` |
| `alt 텍스트` | 따옴표로 감싸기 | `"마라톤 30km 표지판을 지나는 러너의 새벽 풍경"` |
| `프롬프트` | 별도 형식 (§4-4 참조) | — |

#### 4-3-2. 선택 필드 — 빼도 자리 2 통과

| 키 | 용도 |
|---|---|
| `위치` | 문서 안에서 어느 자리에 들어가는지 |
| `위치 의도` | 왜 그 자리인지 한 줄 설명 |
| `캡션` | 이미지 아래 표시될 한 줄 |

#### 4-3-3. 필드 작성 규칙

- 키는 정확히 위 표 그대로 (`종류` ≠ `유형` ≠ `Type`)
- 키와 값 사이는 `**키**: 값` 형태 (`**` 사이에 공백 X)
- `alt 텍스트`와 `캡션`은 **반드시 큰따옴표 `"..."`**로 감싸기
  - 파서가 따옴표를 자동으로 벗긴다
  - 따옴표 없으면 값에 따옴표가 포함된 채로 자리 2·3에 전달됨

### 4-4. 프롬프트 — 특수 형식

```markdown
**프롬프트 (GPT Image 2)**:
> 첫 번째 단락
>
> 두 번째 단락 (여러 단락 가능)
> - 들여쓴 항목 가능
```

- 시작 줄: 정확히 `**프롬프트 (GPT Image 2)**:` (괄호 안 내용은 자유, 콜론 필수)
- 다음 줄부터 `> ` 인용 블록 (공백 1칸 후 내용)
- 단락 구분: 빈 인용 줄 `>`
- 인용 블록이 끝나는 시점이 프롬프트 종료
- 프롬프트 안에 한글 또는 영문 자연어 (GPT Image 2가 둘 다 처리)

### 4-5. 명세 사이 구분

각 명세 사이에 `---` 수평선:

```markdown
### IMG-1 — ...

- 종류: ...
**프롬프트 ...**:
> ...

---

### IMG-2 — ...
```

## 5. 마커-명세 매칭 규칙

자리 2가 가장 엄격하게 검사하는 부분이다.

### 5-1. 1:1 매칭

- 본문에 IMG-1, IMG-2, IMG-3, IMG-4, IMG-5, IMG-6 마커가 있으면
- 명세 섹션에도 정확히 IMG-1 ~ IMG-6 명세가 있어야 함
- 빠진 명세 = "명세 없는 마커" → 자리 2 거부
- 안 쓰인 명세 = "마커 없는 명세" → 자리 2 거부

### 5-2. 식별명 일치

- 본문 `[IMG-1: 도입부 헤더]` ↔ 명세 `### IMG-1 — 도입부 헤더`
- 두 식별명이 글자까지 정확히 일치해야 함
- 띄어쓰기·괄호·구두점 차이도 거부 대상

좋은 예:
```
본문: [IMG-3: 800kcal 인포그래픽]
명세: ### IMG-3 — 800kcal 인포그래픽
```

나쁜 예:
```
본문: [IMG-3: 800kcal 인포그래픽]
명세: ### IMG-3 — 800kcal 인포그래픽 (단일 핵심 사실 시각화)  ❌ 명세에 부가 설명 추가
```

부가 설명이 필요하면 `위치 의도` 필드에 적는다. 식별명에 넣지 않는다.

## 6. 시리즈 ID 규칙

자리 2가 글에 어떤 시리즈 톤을 적용할지 판단하는 기준.

### 6-1. 파일명에서 자동 추출

- `journal-01-*.md` → 시리즈 ID `journal-01`
- `journal-02-*.md` → 시리즈 ID `journal-02`

자리 2의 Skill이 파일명 prefix로 시리즈를 자동 판별한다. Claude는 별도 메타데이터로 시리즈 ID를 명시할 필요 없음 — 파일명이 곧 시리즈 결정자.

### 6-2. 시리즈별 톤은 별도 파일에 정의

`series_blocks/journal-01.yaml`, `series_blocks/journal-02.yaml` 등.

Claude가 글 쓸 때 시리즈별 톤이 어떻게 정의됐는지는 `active_series.md` 참조 (별도 산출물).

## 7. 본문 외 요소 사양

### 7-1. YAML 프론트매터

기존 룰북(mode_journal.md, mode_tofu.md)의 형식 그대로. 자리 2는 프론트매터를 직접 읽지 않으나, 자리 3의 자사몰 변환 단계가 읽는다.

### 7-2. 면책 문구

본문 종료 후, 이미지 명세 섹션 시작 전에 위치. 자리 3의 `regulation_check.py`가 면책 문구 마커를 검사한다.

다음 키워드 중 **최소 2개** 포함:
- "제품정보와 관련 없는"
- "학술 자료에 근거한"
- "일반 건강정보"
- "의학적 진단을 대체"

기존 룰북의 표준 면책 문구를 그대로 쓰면 4개 다 매칭되어 통과.

### 7-3. 참고문헌

면책 문구 다음, 이미지 명세 섹션 전. 자리 2·3에 영향 없음 (정보용).

## 8. 전체 글 구조 — 자리 2 관점

```
1. YAML 프론트매터 (---로 둘러싼)
2. 제목 (# h1)
3. [IMG-1: ...] 마커
4. 핵심 요약박스
5. INTRO ~ H2 본문 (마커 분산 배치)
6. OUTRO
7. 면책 문구
8. 참고문헌 (선택)
9. ---
10. ## 이미지 명세
11. ### IMG-1 — ... (메타필드 + 프롬프트)
12. ---
13. ### IMG-2 — ...
14. ... (반복)
```

이 순서가 유지되어야 자리 2 파서가 본문과 명세 섹션을 올바르게 분리한다.

## 10. 빠른 검증 체크리스트

```
[ ] 파일명: journal-NN-X.md (소문자 + 하이픈)
[ ] 모든 마커: [IMG-N: 식별명] 단독 줄
[ ] 마커 번호: 1부터 빠짐없이 순차
[ ] 명세 섹션: ## 이미지 명세 헤더로 시작
[ ] 각 명세: ### IMG-N — 식별명 (식별명 본문과 일치)
[ ] 모든 명세에 필수 4필드: 종류, 비율, alt 텍스트, 프롬프트
[ ] alt 텍스트와 캡션: 큰따옴표로 감싸기
[ ] 프롬프트: **프롬프트 (GPT Image 2)**: + > 인용 블록
[ ] 마커 수 == 명세 수 (1:1)
[ ] 면책 문구 마커 2개 이상 포함
```
