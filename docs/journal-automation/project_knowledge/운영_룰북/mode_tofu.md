## 1. 채널 정의

네이버 블로그 TOFU는 검색 유입과 러닝 과학 브랜드 인지를 위한 순수 교육 콘텐츠다. 발행 주체 페르소나는 "러닝을 사랑하는 과학 탐구자" — 건기식 업체와의 연결은 어디에도 드러내지 않는다.

대부분의 글은 **Journal에서 파생되는 클러스터**다. Journal 한 편의 H2 하나가 네이버 글 한 편의 씨앗이 된다. 같은 메시지의 다른 화법이지, 새로 시작하는 글이 아니다.

예외적으로 시즌 트렌드 대응이나 외부 화제 응답 같은 독립 주제로 작성하기도 하지만, 이는 한정적이다. YAML 프론트매터의 `journal_source` 필드에 출처 Journal을 명시하거나 "독립"으로 표기한다.

분량은 클러스터 약 1,500자, Pillar 약 2,500~3,500자가 표준. Pillar는 12주 중 종합 가이드 자리(W6-화, W11-화)에 한정된다.

## 2. TOFU 절대 금지 (Blocklist)

다음 표현이 등장하면 → 문장 삭제 + `[TOFU-BLOCKED: 사유]` 표시.

| 금지 | 사유 |
|------|------|
| 지구력코어 (제품명) | TOFU에서 제품 인지 자체가 광고 판정 트리거 |
| 옥타코사놀 (성분명) | TOFU에서 특정 성분 언급 = 제품 연상 유도 |
| 자사몰/스마트스토어 URL | 구매 경로 제공 = 판매 촉진 의도 |
| "보충제 추천", "건기식 추천" | 제품군 유도 표현 |
| "에너지 부스터", "에너지 폭발" | 과대 효능 암시 + 금지 표현 우회 시도 |
| 5대 금지어 (스테미너/피로/파워/젊음/힘없는) | 옥타코사놀 5대 금지 표현 |
| 의약품 오인 용어 (복용/효능/효과/임상시험/처방) | 건기식↔의약품 구분 위반 |

이 Blocklist는 **본문 텍스트 + 이미지 안의 텍스트 + alt 텍스트 + 캡션 + 해시태그** 모두에 적용된다.

## 3. Journal에서 네이버 블로그로

### 3-1. 같은 정보, 다른 화법

Journal에서 출발한 네이버 글은 **같은 정보를 검색 유입자에게 가장 친근하게 전달**하는 작업이다. 단순 톤 변경이 아니다. 글의 목적이 다르기 때문에 구조도 일부 다르다.

| 항목 | Journal H2 | 네이버 클러스터 |
|------|-----------|--------------|
| 화자 | 객관적 주어 ("러너는") | 1인칭 가능 ("저도 ~합니다") |
| 종결어미 | ~다, ~한다 | ~입니다, ~죠, ~네요 |
| H2 제목 | 명사형/단언형 | 질문형 50% 이상 |
| 핵심 요약박스 | 매거진 단언형 | 친근형 |
| FAQ | 매거진 톤 | 친근 톤 |
| 키워드 자연 배치 | 약함 | 강함 (제목·첫 2문장·H2·말미) |
| 내부링크 | 없음 | 1~3개 |
| 이미지 | 5~8장 | 8~13장 (Pillar 10~15장) |

Journal이 **머무는 깊이**를 위한 글이라면, 네이버는 **검색으로 들어와 답을 찾고 가는** 글이다. 이 차이가 도입부와 결말 처리, 그리고 이미지 밀도까지 좌우한다.

### 3-2. 도입부에서 달라지는 것

Journal 도입부가 관찰자 시점의 장면("한 러너가 30km 지점에서 멈춰선다")이라면, 네이버 도입부는 친근 시점이다 — "30km 지점에서 다리가 무거워진 경험, 다들 한 번씩은 있으시죠"처럼 독자에게 직접 말을 건다.

도입부 다음에는 검색 의도에 곧바로 답하는 두 문장이 와야 한다. 이 두 문장 안에 타겟 키워드와 핵심 답변이 모두 들어간다. AI 브리핑이 정답형 한 문장으로 추출하는 단위가 바로 이 자리다.

### 3-3. 본문에서 보강되는 것

Journal H2의 분석을 그대로 가져오되, 러너의 일상 언어로 풀어준다. "글리코겐 절약(Glycogen Sparing)"이라는 용어가 등장하면 곧바로 "쉽게 말해 같은 거리를 더 적은 연료로 달리는 방법" 같은 번역이 따라붙는다.

비교표는 Journal에서 가져오거나 새로 만들고, 표 다음에는 "즉, 짧고 빠른 운동은 글리코겐, 길고 느린 운동은 지방이 주연료입니다" 같은 한 줄 정리로 닫는다.

이미지도 Journal보다 많이 추가된다 — Journal의 5~8장이 네이버에서는 8~13장으로 늘어난다. 이는 모바일 70%+ 환경에서 "3줄 텍스트 + 1 이미지" 리듬을 만들기 위한 것이다.

### 3-4. 결말에서 달라지는 것

Journal이 도입 장면을 회수하며 한 줄 단언으로 닫는다면, 네이버는 핵심 메시지를 한 번 더 반복하고 다음 글로 자연스럽게 안내한다. 같은 Journal에서 파생된 자매 클러스터 글이 있다면 "함께 읽으면 좋은 글"에 우선 배치한다.

## 4. 본문 구조

```
[제목] 질문형 또는 키워드 포함형

[IMG-1: 헤더] 마커

[핵심 요약박스] ← AEO 필수
> **핵심 요약**
> [한 문장 직접 답변]
> - 부연 불렛 3~5개

[도입부]
- 친근 시점 장면 또는 독자에게 말 걸기
- 검색 의도에 답하는 두 문장 (타겟 키워드 + 핵심 답변)
- 정보갭 1개 열기

[H2-1, H2-2] (필요 시 H3 보조)
  - 핵심 메커니즘 + 실전 적용
  - 비교표 1개+ ← AEO 필수 (Pillar는 2개+)
  - 일상 언어 번역 병행
  - 본문 중간 마커 3~5개 (3줄 텍스트 + 1 이미지 리듬)

[FAQ 섹션] ← AEO 필수
  Q. [실제 검색 쿼리와 일치하는 질문 1]
  Q. [실제 검색 쿼리와 일치하는 질문 2]
  Q. [질문 3 — Cluster 3개, Pillar는 5~7개]

[결론]
- 핵심 메시지 재진술
- 다음 글 또는 자매 클러스터 글로 안내

[함께 읽으면 좋은 글] ← 내부링크 필수
- 기발행 관련 글 1~3개
- 미발행은 [내부링크 예정: 클러스터 제목]

[이미지 명세 섹션] ← 글 맨 끝
- IMG-1부터 IMG-N까지 순서대로 명세 (§9.5-4)
```

분량 가이드는 Cluster 약 1,500자, Pillar 약 2,500~3,500자. 이미지는 Cluster 8~13장, Pillar 10~15장. 도입부와 결론은 짧게, 본문이 글의 무게중심을 차지한다.

## 5. AEO Foundation 3요소 (필수)

### 5-1. 핵심 요약박스 — 한 문장 직접 답변 + 부연

```
> **핵심 요약**
> 마라톤 후반에 페이스가 무너지는 가장 큰 원인은 글리코겐 고갈입니다.
>
> - 체내 글리코겐 약 2,000kcal vs 풀마라톤 소모 2,500~3,000kcal
> - 30km 지점부터 고갈 위험이 급증
> - 지방 산화 효율을 높이면 글리코겐 절약 가능
> - 훈련(존2)과 영양 전략을 모두 병행해야 함
```

서론 직전, 첫 H2 이전 위치. 첫 줄은 검색 의도에 대한 한 문장 직접 답변 — AI가 정답형으로 추출하는 단위다. 부연 불렛 3~5개. 친근 톤. 제품명/성분명 0회.

### 5-2. 비교표 — Cluster 1개+, Pillar 2개+

2개 이상의 항목을 비교하거나 3개 이상의 데이터 포인트가 있으면 반드시 표 사용. AI가 정형 데이터를 우선 추출한다.

```markdown
| 에너지원 | 저장량 | 분해 속도 | 고강도 의존도 |
|---------|--------|----------|-------------|
| 글리코겐 | ~2,000kcal | 빠름 | 높음 |
| 지방 | ~70,000kcal+ | 느림 | 낮음 |
```

표 다음에 한 줄 정리를 붙인다 — 표가 보여주는 핵심을 자연어로 닫는 마무리. 비교표 직후 데이터 시각화 IMAGE 박스를 배치하면 효과가 두 배가 된다.

### 5-3. FAQ 섹션 — 3~5개 (Pillar는 5~7개)

```markdown
### 자주 묻는 질문

#### Q. 마라톤 페이스 드롭은 초보자만 겪나요?
엘리트 러너도 글리코겐 고갈을 경험합니다. 다만 훈련된 러너일수록 ...

#### Q. 존2 트레이닝이 페이스 드롭 방지에 도움이 되나요?
존2(최대심박수 60~70%) 훈련은 지방 산화 효율을 높여 ...
```

결론 직전 위치. H3 "자주 묻는 질문" → H4 각 질문(Q. 으로 시작). 답변은 두세 문장, 친근 톤. 제품명/성분명 0회.

질문 출처는 자동완성, AI 검색어 제안, '관련 질문' 박스, 커뮤니티(런갤·네이버 카페) 등 다양한 곳에서 추출한다. 한 곳에서만 뽑으면 질문이 단조로워진다.

> 키워드/질문 발굴 5단계: `키워드_리서치_가이드.md`

## 6. H2 질문형 50% 이상

TOFU 네이버 블로그 H2의 절반 이상은 질문형. 사용자 검색이 단어→문장형으로 전환된 환경 대응이다.

| 패턴 | 예시 |
|------|------|
| ❌ 키워드 나열형 | "ATP-PCr 시스템의 작동 원리" |
| ✅ 질문형 | "100m 전력질주는 왜 30초밖에 못 버틸까?" |
| ✅ "왜 ~인가" | "마라톤 후반에 왜 다리가 무거워질까?" |
| ✅ "어떻게 ~하나" | "탄수화물 로딩, 어떻게 해야 효과적일까?" |
| ✅ "~할 때 ~해야 하나" | "달리기 전에 탄수화물을 먹어야 할까?" |

키워드 포함형 H2도 50% 한도 내에서 사용 가능 ("존2 트레이닝이 만드는 변화"처럼).

## 7. 내부링크

작성 시 `콘텐츠_발행_로그.md`에서 기발행 글 목록을 확인하고, 본문 하단 "함께 읽으면 좋은 글" 섹션에 관련 글 1~3개를 배치한다. 미발행 연결 대상은 `[내부링크 예정: 클러스터 제목]` 태그를 부착한다. 같은 Journal 시리즈에서 도출된 자매 클러스터의 매핑은 `발행_매핑_가이드.md` 참조.

링크 방향:
- TOFU ↔ TOFU 양방향 허용
- TOFU → MOFU/BOFU/제품 페이지 절대 금지 (규제 분리 원칙)
- 자사몰 Journal로의 링크는 일반적으로 권장하지 않음. Journal이 본문에서 제품을 추천하지 않는 구조이므로 기술적으로는 가능하지만, 신생 블로그 단계에서는 자사몰 신호를 만들지 않는 것이 안전하다.

앵커 텍스트는 키워드 포함 서술형. "여기를 클릭" 같은 비서술형 금지.

같은 Journal에서 파생된 자매 클러스터 글은 "함께 읽으면 좋은 글"에서 서로 링크한다.

## 8. 톤 세부 규칙

### 8-1. 종결어미

`~입니다 / ~합니다`가 60~70%, `~죠 / ~네요 / ~군요` 같은 변주가 30~40%. 명사형 종결도 가끔 들어간다. 3문장 연속 같은 종결어미는 금지 — 같은 운율이 반복되면 글이 굳는다.

### 8-2. 화자 운용

"저도 30km 지점에서 멈춰선 적이 있어요"처럼 1인칭 경험 공유는 OK. "여러분도 이런 경험 있으시죠?" 같은 질문 던지기도 OK. 다만 과도한 친근감은 피한다. 러너 동료가 다른 러너에게 알려주는 톤이지, 강사가 학생에게 가르치는 톤이 아니다.

### 8-3. 학술 인용

본문 중 "Kim et al.(2023) 연구에 따르면..." 같은 인라인 형식. 일상 언어로 번역 병행 필수 — 인용 문장 다음에 "쉽게 말하면..."이 곧바로 따라붙어야 한다. 글 하단에 참고문헌 풀 레퍼런스를 정리한다.

### 8-4. 모바일 가독성

문단은 모바일 3~4줄 단위. 한 문장이 2줄 넘으면 끊는다. 6줄 이상 연속 텍스트 벽은 만들지 않는다.

### 8-5. 흡입력

흡입력 룰북의 원리를 모두 적용한다. 도입부에 장면, 정보갭 2~3개를 1~3문단 내에 닫기, H2 전환점에 버킷 브리게이드, 도입부와 본론 중반에 패턴 인터럽트.

> 상세: `흡입력_글쓰기_룰북_v2.md`

## 9. SEO 규칙

타겟 키워드는 제목, 첫 두 문장, H2 최소 1개, 마지막 문단에 자연스럽게 배치한다. 첫 두 문장은 도입부 장면 다음에 곧바로 와서 검색 의도에 직접 답해야 한다 — AI 스니펫 추출 자리다.

**이미지 SEO**: 모든 이미지의 alt 텍스트에 타겟 키워드를 자연 삽입. 캡션도 키워드 자연 삽입 기회로 활용. 자세한 이미지 작업은 §9.5 참조. 메타 디스크립션은 120자 이내, 키워드 포함, 클릭을 유도하는 문장으로 작성한다.

## 9.5. 이미지 — 네이버 블로그 모드

> 상세 프롬프트 템플릿은 `이미지_가이드.md` §4 참조.

### 9.5-1. 장수와 리듬

네이버 블로그 본문은 모바일 70%+ 환경이다. **"3줄 텍스트 + 1 이미지"** 리듬을 기본으로 한다.

| 글 분류 | 이미지 장수 |
|---------|----------|
| Cluster (약 1,500자) | 8~13장 |
| Pillar (약 2,500~3,500자) | 10~15장 |

이미지가 부족하면 텍스트 벽이 만들어져 모바일 이탈률이 급증한다. 반대로 너무 많아도(15장 초과) 로딩 지연 + 본문 흐름 단절이 발생한다.

### 9.5-2. 종류 비율

| 종류 | 비중 | 주된 위치 |
|------|------|---------|
| 분위기 사진 | 30~40% | 헤더, 섹션 전환 |
| 데이터 시각화 (차트, 그래프) | 20~30% | 비교표 직후·숫자 언급 직후 |
| 다이어그램 / 인포그래픽 | 20~30% | 메커니즘 설명 직후 |
| 인물 장면 (러너 액션) | 10~20% | 본문 중간 호흡 조절 |

한 글에 **최소 3종 이상 혼합**한다.

### 9.5-3. 네이버 톤에 맞는 이미지

네이버 블로그는 "러너 동료" 톤이다. Journal보다 좀 더 친근하고 따뜻해도 된다. 다만 다음은 동일하게 유지한다.

- **컬러 팔레트**: `#FAFAF7` / `#1A2B3C` / `#E8743C` (브랜드 톤 일관)
- **모델 가이드**: 30대 후반~40대 한국 남성 러너
- **규제**: 알약·캡슐·제품 사진·"옥타코사놀"·"지구력코어" 텍스트 일체 금지
- **금지**: 의사·흰 가운·청진기·병원 장면

Google AI Search 기준으로 이미지도 본문 이해를 돕는 실제 정보 자산이어야 한다. 단순 장식 이미지, 키워드만 넣은 alt 텍스트, 본문 내용과 맞지 않는 이미지는 쓰지 않는다.

### 9.5-4. 본문 표기 — 마커 + 명세 섹션 분리

본문 중 이미지가 들어가야 할 자리에 다음 마커를 단독 줄에 삽입한다.

```
[IMG-1: 헤더 사진]
```

본문 종료(참고문헌 뒤) 후 글 맨 끝에 **이미지 명세 섹션**을 두고 마커 순서대로 다음 형식으로 작성한다.

```markdown
---

## 이미지 명세

### IMG-1 — 헤더 사진

- 종류: 분위기 사진
- 위치: 핵심 요약박스 직전
- 위치 의도: [한 줄]
- 비율: 16:9
- alt 텍스트: "[타겟 키워드 자연 삽입, 한 줄]"
- 캡션: "[친근 톤 한 줄, ~입니다/~죠 사용]"

**프롬프트 (GPT Image 2)**:
> [자연어 프롬프트]

---

### IMG-2 — ...
```

캡션 톤은 본문과 같은 친근형. "30km 지점, 다들 한 번씩 무너져보신 그 자리예요." 같은 ~예요/~죠/~네요 종결. 매거진 단언형은 피한다.

마커 번호와 명세의 IMG 번호는 반드시 1:1 일치.

### 9.5-5. alt 텍스트 — SEO 핵심

네이버 검색 노출은 alt 텍스트의 영향이 크다. 모든 이미지의 alt 텍스트에 다음을 적용한다.

- **타겟 키워드 1개 자연 삽입** — 제목과 같은 키워드 또는 변형
- **한 줄, 따옴표 안에**
- **"이미지", "사진" 같은 단어는 넣지 않음** (스팸 시그널)
- **반복 회피** — 글 안에서 alt 텍스트가 동일하면 안 됨

좋은 예: `"마라톤 30km 지점을 통과하는 러너의 새벽 풍경"`
나쁜 예: `"러너 사진 이미지"`, `"마라톤"`, `"runner-30km.jpg"`

---

## 10. 5중 체크리스트

**규제 (5항목)**
- [ ] "옥타코사놀" 0회 등장 (본문 + 이미지 박스 + alt + 캡션 모두)
- [ ] "지구력코어" 0회 등장 (본문 + 이미지 박스 + alt + 캡션 모두)
- [ ] 제품·보충제·건기식 구매 유도 문구 0건
- [ ] 자사몰/스토어 URL 0건
- [ ] 5대 금지어 + 의약품 오인 용어 0회

**AEO (5항목)**
- [ ] 핵심 요약박스: 한 문장 직접 답변 + 부연 불렛 3~5개 (서론 직전)
- [ ] 비교표: Cluster 1개+, Pillar 2개+
- [ ] FAQ: Cluster 3~5개, Pillar 5~7개 (Q&A H3+H4 구조)
- [ ] 첫 두 문장: 타겟 키워드 + 핵심 답변
- [ ] H2 질문형 50% 이상

**내부링크 (4항목)**
- [ ] 기발행 관련 글 내부링크 1~3개 배치
- [ ] 내부링크 대상이 MOFU/제품 페이지가 아닌지 확인
- [ ] 미발행 연결 대상에 [내부링크 예정] 태그
- [ ] 자매 클러스터 글 상호 링크 (Journal 분할 시)

**흡입력 (8항목)**
- [ ] 정보갭 2~3개, 모두 1~3문단 내 닫힘
- [ ] 도입부에 장면(scene) — 시간+장소+감각
- [ ] 글 전체에 감정 톤 1가지 일관
- [ ] H2 전환점에 버킷 브리게이드
- [ ] 도입부 + 본론 중반 패턴 인터럽트 각 1개
- [ ] 3문장 연속 같은 길이·종결어미 없음
- [ ] 모바일 6줄 이상 연속 텍스트 벽 없음
- [ ] 종결어미 ~입니다 60~70% + 변주 30~40%

**이미지 (5항목)**
- [ ] 본문에 마커 8~13개 (Pillar는 10~15개) — `[IMG-N: 식별명]` 단독 줄 형식
- [ ] 분위기 사진 / 데이터 시각화 / 다이어그램 / 인포그래픽 / 인물 장면 중 최소 3종 혼합
- [ ] **마커-명세 동기화**: 본문 모든 마커가 명세 섹션의 `### IMG-N`과 1:1 일치, 누락/고아 없음
- [ ] 모든 명세에 GPT Image 2 자연어 프롬프트 + 모든 alt 텍스트에 타겟 키워드 자연 삽입 + 중복 회피
- [ ] 브랜드 톤(컬러·분위기 키워드·모델 가이드) 일관성

## 11. 작업 흐름

사용자 요청: `Journal №01-A H2-1 기반 네이버 글 작성해줘` 또는 `[독립] 5월 마라톤 컨디셔닝 글 작성해줘`

**설계**
1. 출처 확인 — Journal 분할이면 해당 H2 추출, 독립이면 주제·키워드 리서치
2. 핵심 메시지 한 문장 정리 — One Message Rule
3. 도입 장면과 정보갭 2~3개 위치 구상
4. 이미지 8~13개 위치 사전 설계 (3줄 텍스트 + 1 이미지 리듬)

**작성**
5. 질문형 제목과 핵심 요약박스 (한 문장 직접 답변 + 부연 불렛)
6. **IMG-1 마커 (헤더 자리)**
7. 도입부 — 친근 시점 장면 + 검색 의도 직답 두 문장
8. H2 두 개 (질문형 1개 이상, 비교표 1개 이상). 본문 중간에 **마커 4~7개 분산 배치**
9. FAQ 3~5개 — 자동완성·관련 질문·커뮤니티에서 발굴
10. 결론 — 핵심 메시지 재진술 + 다음 글 안내
11. 내부링크 배치
12. **이미지 명세 섹션 작성** — IMG-1부터 순서대로 명세(종류/위치/비율/alt/캡션/프롬프트) 정리

**검수**
13. 5중 체크리스트 실행 (총 27항목) + 마커-명세 동기화 검증
14. 실패 항목이 있으면 출력 전 사용자에게 보고
15. YAML 프론트매터 + .md 파일 출력

---

## 12. 출력 형식

```yaml
---
title: "[질문형 제목] (예: 마라톤 30km에서 다리가 멈추는 이유는?)"
channel: naver_blog
funnel_stage: TOFU
content_role: Cluster | Pillar
journal_source: "Journal №01-A" | "독립"
journal_h2_index: 1 | 2 | "전체"
category: 문제고민 | 비교 | BestInClass
target_keywords:
  primary: "마라톤 30km 페이스 드롭"
  secondary: ["글리코겐 고갈", "마라톤 후반 페이스"]
word_count: 약 1,500자
image_count: 10
review_required: N
review_note: "심의 불필요 — TOFU, 제품/성분 언급 없음"
date_drafted: YYYY-MM-DD
---
```

본문 구조:
1. 제목
2. **IMG-1 마커 (헤더 자리)**
3. 핵심 요약박스
4. 도입부 (친근 시점 장면 + 검색 의도 직답)
5. H2-1 (본문 + **마커 2~3개**)
6. H2-2 (본문 + **마커 2~3개**)
7. 비교표 1개+ (직후 데이터 시각화 마커 권장)
8. FAQ 3~5개
9. 결론
10. 함께 읽으면 좋은 글 (내부링크)
11. (글 하단) 참고문헌
12. **이미지 명세 섹션** — IMG-1부터 IMG-N까지 순서대로 명세 정리
