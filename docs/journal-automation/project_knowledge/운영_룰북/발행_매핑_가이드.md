# 발행 매핑 가이드

> Journal과 네이버 블로그 클러스터가 어떻게 연결되는지를 정의하는 매핑 룰. 발행 시점이나 주차별 일정이 아니라, **한 Journal에서 네이버 글이 어떻게 도출되는지**의 구조를 다룬다.

---

## 1. 한 사이클의 구조

한 Journal 시리즈가 네이버 블로그와 카루셀로 펼쳐지는 흐름은 다음과 같다.

```
[Step 1]  Journal №X-A 마스터 작성 (자사몰)
              ↓
[Step 2]  №X-A에서 네이버 클러스터 2편 분할 발행
              ↓
[Step 3]  Journal №X-B 마스터 작성 (자사몰)
              ↓
[Step 4]  №X-B에서 네이버 클러스터 2편 분할 발행
              ↓
[Step 5]  네이버 클러스터 글 → 카루셀 원자화 (상시)
              ↓
[Step 6]  다음 Journal №X+1 시작
```

한 사이클의 산출물:
- 자사몰 Journal: 2편 (A + B)
- 네이버 클러스터: 4편 (Journal H2 4개에서 각 1편씩)
- 인스타 카루셀: 4~8개 (네이버 글당 1~2개)

발행 시점은 사용자가 순차적으로 진행한다. 매핑 가이드는 시점이 아니라 **순서와 연결**을 정의한다.

---

## 2. Journal H2 → 네이버 클러스터 매핑

### 2-1. 1:1 매핑 원칙

Journal 한 편의 H2 한 개가 네이버 클러스터 한 편의 씨앗이 된다. Journal A/B 시리즈 1세트(H2 4개)에서 네이버 클러스터 4편이 도출된다.

```
Journal №X-A H2-1  →  네이버 클러스터 #1
Journal №X-A H2-2  →  네이버 클러스터 #2
Journal №X-B H2-1  →  네이버 클러스터 #3
Journal №X-B H2-2  →  네이버 클러스터 #4
```

### 2-2. 변환 시 무엇이 달라지나

같은 메시지의 다른 화법이지만, 채널 목적이 다르므로 다음이 달라진다.

| 항목 | Journal H2 | 네이버 클러스터 |
|------|-----------|--------------|
| 분량 | 약 1,200자 | 약 1,500자 |
| 화자 | 객관적 주어 | 1인칭 가능 |
| 종결어미 | ~다, ~한다 | ~입니다, ~죠 |
| H2 제목 | 명사형/단언형 | 질문형 50% 이상 |
| 핵심 요약박스 | 매거진 단언형 | 친근형 |
| FAQ | 매거진 톤 3~5개 | 친근 톤 3~5개 |
| 키워드 자연 배치 | 약함 | 강함 |
| 내부링크 | 없음 | 1~3개 |

세부 변환 규칙은 `mode_tofu.md` §3 참조.

### 2-3. 자매 클러스터 — 상호 링크

같은 Journal에서 도출된 클러스터 4편은 서로를 "자매 클러스터"로 인식하고, "함께 읽으면 좋은 글" 섹션에서 상호 링크한다.

```
클러스터 #1 ↔ #2 ↔ #3 ↔ #4 (상호 링크)
```

이 상호 링크가 네이버 C-Rank의 주제 일관성 신호를 강화하고, 사용자 체류 시간을 늘린다.

## 3. Pillar 글 — 사이클의 통합 자산

Pillar는 클러스터들의 종합 가이드 역할을 하는 깊이 있는 글이다(약 2,500~3,500자). 한 Journal 사이클이 끝나거나 여러 사이클이 누적된 시점에 작성한다.

### 3-1. Pillar의 역할

- 여러 클러스터 글을 하나의 종합 가이드로 통합
- 네이버 검색에서 "마라톤 후반 페이스 종합 가이드" 같은 광범위한 검색 쿼리 대응
- 클러스터들이 Pillar로 모이고, Pillar가 다시 클러스터들로 향하는 **허브 구조** 형성

### 3-2. Pillar 작성 시점

**원칙**: 통합할 클러스터가 충분히 쌓였을 때.

- 한 Journal 시리즈(클러스터 4편)가 모두 발행된 후 → 시리즈 종합 Pillar 가능
- 여러 Journal 사이클이 누적된 후 → 광범위한 종합 Pillar 가능

### 3-3. Pillar의 내부링크 구조

```
Pillar
  ├─→ 클러스터 #1 (상세 1)
  ├─→ 클러스터 #2 (상세 2)
  ├─→ 클러스터 #3 (상세 3)
  └─→ 클러스터 #4 (상세 4)

각 클러스터
  └─→ Pillar (상위 종합)
```

Pillar 본문에서는 각 섹션이 끝날 때마다 "더 깊이 보고 싶다면" 식으로 해당 클러스터 글을 링크한다. 클러스터 글에서는 도입부나 결론에 "이 주제의 종합 가이드는 이 글에서" 식으로 Pillar를 링크한다.

## 4. 카루셀 원자화

### 4-1. 입력은 네이버 클러스터, 출력은 카루셀

카루셀의 입력은 Journal이 아니라 **네이버 클러스터 글**이다. Journal에서 직접 카루셀로 만들지 않는다.

```
Journal H2  →  네이버 클러스터  →  카루셀
```

이유: 네이버 클러스터가 이미 검색 의도와 친근 톤으로 풀어진 상태이고, 카루셀의 짧은 슬라이드 톤과 더 가깝다.

### 4-2. 1:1 또는 1:2 매핑

네이버 클러스터 한 편에서 카루셀 1~2개가 도출된다.

- **1:1 매핑** — 클러스터의 핵심 메시지를 한 카루셀로 압축
- **1:2 매핑** — 메커니즘 카루셀 + 실천 팁 카루셀로 분리

세부 변환 규칙은 `mode_instagram.md` 참조.

## 5. 현재 확정된 것

| 항목 | 상태 |
|------|------|
| Journal №01 (30km 페이스 유지) | ✅ A/B 분할 확정 |
| Journal №01-A "왜 30km에서 무너지는가" | ✅ H2 구조 확정 (글리코겐 2,000kcal와 마라톤 2,800kcal / 남은 30%에서 갈리는 두 부류) |
| Journal №01-B "30km 이후 페이스를 지키는 법" | ✅ H2 구조 확정 (지방을 더 잘 태우는 몸 만들기 / 레이스 당일 탄수화물 시간당 g 계산) |
| Journal №02 (대회 준비 루틴) | ⏳ 작성 시점에 분할 결정 |
| Journal №03 (옥타코사놀 원료) | ⏳ 작성 시점에 분할 결정. 가장 마지막. 규제 가장 정밀하게. |

> **H2 제목 명명 원칙** (mode_journal.md §3-2 참조): "연료의 산술" "두 개의 연료, 다른 속도" 같은 시적 추상명사구는 피한다. 숫자나 구체적 사실이 들어간 명사구가 더 강하다. 위 표의 제목들은 작성 시점에 다시 다듬어도 된다 — 다만 추상보다 구체로 가는 방향만 유지한다.

### 5-1. Journal №01 → 네이버 클러스터 4편 매핑 (확정)

| 출처 | 네이버 클러스터 (가제) | 핵심 키워드 |
|------|---------------------|-----------|
| №01-A H2-1 (글리코겐 2,000kcal와 마라톤 2,800kcal) | "마라톤 30km에서 다리가 멈추는 이유 — 800kcal 부족분 계산" | 마라톤 30km 벽, 글리코겐 고갈 |
| №01-A H2-2 (남은 30%에서 갈리는 두 부류) | "글리코겐과 지방, 러너 몸은 둘을 어떻게 나눠 쓰나" | 글리코겐 vs 지방, 에너지 시스템 |
| №01-B H2-1 (지방을 더 잘 태우는 몸 만들기) | "존2 트레이닝이 마라톤 후반 페이스에 미치는 영향" | 존2 트레이닝, 지방 산화 |
| №01-B H2-2 (레이스 당일 탄수화물 시간당 g 계산) | "마라톤 당일 탄수화물 섭취, 시간당 몇 g이 적정한가" | 마라톤 탄수화물, 레이스 영양 |

각 네이버 글의 제목·키워드는 작성 시점에 자동완성/관련 질문에서 다시 검증한다.

## 6. 콘텐츠_발행_로그.md 와의 관계

이 매핑 가이드는 **계획**이고, `콘텐츠_발행_로그.md`는 **실행 기록**이다.

- 매핑 가이드: "어떤 Journal에서 어떤 네이버 글이 나올지"의 구조
- 발행 로그: "실제로 언제 무엇을 발행했는지"의 기록

새 글을 발행할 때마다 발행 로그에 추가하고, 발행 로그를 보면 자매 클러스터·Pillar·내부링크 대상을 파악할 수 있다.

---

## 7. 매핑 추가 시 절차

새 Journal을 작성할 때 다음을 매핑 가이드에 추가한다.

1. Journal 분할 패턴 결정 (진단/처방, 원리/실천, 일반/심화 중)
2. A/B 각각의 H2 2개 제목 확정
3. 각 H2 → 네이버 클러스터 가제 매핑
4. 자매 클러스터 상호 링크 관계 확인
5. 통합 가능한 Pillar 후보 검토 (선택)

이 절차를 거쳐 §5 표를 업데이트한다.
