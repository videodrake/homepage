# mode_instagram.md

> 인스타그램 카루셀 변환 시 로드되는 모드 가이드. 네이버 블로그 클러스터를 카루셀로 원자화하는 작업을 다룬다.
> v2 (2026-04-28). 슬라이드별 이미지 프롬프트 의무화.

---

## 1. 채널 정의

인스타그램은 브랜드 인지도 채널이다. SEO 부스터가 아니다.

카루셀의 입력은 Journal이 아니라 **네이버 블로그 클러스터 글**이다. Journal에서 직접 카루셀로 가지 않는다 — Journal은 매거진 톤이라 짧은 슬라이드와 거리가 있고, 네이버 클러스터는 이미 친근 톤으로 풀어진 상태라 카루셀 톤과 가깝기 때문이다.

```
Journal H2 → 네이버 클러스터 → 카루셀
```

**카루셀에서 슬라이드 자체가 이미지다.** 따라서 다른 채널과 달리 본문 곳곳에 박스를 삽입하는 게 아니라, **슬라이드 N장 전부에 이미지 프롬프트를 1:1로 매칭**한다.

---

## 2. 현실적 기대치

- 교육형 카루셀 참여율: 1.5~3% (기본 시나리오). 4.7% 이상은 비현실적 — 인스타 전체 평균 0.48% 대비 이미 3~6배
- DM 전환율: 5~8% (12~18%는 비현실적)
- DM 자동화 도입: 팔로워 500+ 이후 검토

이 수치를 KPI 기준선으로 삼고, 단기간에 이를 초과하는 결과를 기대하지 않는다.

---

## 3. One Message Rule — 카루셀에서 가장 엄격

카루셀은 설명이 아니라 **확신을 주는 콘텐츠**다.

- 1장 훅 = 핵심 메시지의 질문형 (이것 하나로 스크롤을 멈추게)
- 중간 슬라이드 = 그 메시지의 근거 최대 3개 (3개 넘으면 잘라낸다)
- 마지막 장 = 핵심 메시지를 확신으로 전환하는 한 줄
- "이것도 알려줘야 해"를 참는 것이 카루셀의 핵심 역량
- 말하고 싶은 게 5개라면 → 카루셀 5개를 만드는 것이 정답

블로그가 "이해시키는 것"이라면, 카루셀은 "확신시키는 것"이다.

**카루셀 작성 전 반드시 확인**: "이 카루셀이 남기는 한 문장이 뭔가?"

---

## 4. TOFU 규칙 동일 적용

인스타 카루셀은 TOFU와 동일한 순수 교육 콘텐츠다.

- 제품명 "지구력코어" 완전 금지
- 성분명 "옥타코사놀" 완전 금지
- 자사몰/스토어 URL 금지
- 보충제·건기식 구매 유도 금지
- 5대 금지어 + 의약품 오인 용어 0회
- **이미지 내 텍스트에도 동일 적용** (Meta Rosetta OCR + AI캅스 이중 탐지로 잡힌다)
- **이미지 프롬프트 안에서도 금지** — GPT Image 2가 텍스트를 그대로 그릴 수 있으므로 프롬프트에 "옥타코사놀"을 적으면 이미지에 그대로 박힌다

---

## 5. 카루셀 규격

- **슬라이드 수**: 8~10장 (교육 카루셀) / 5~7장 (팁/리스트 카루셀)
- **비율**: 4:5 (1080×1350px) — 2026 인스타 피드 표준 (3:4 권장이었으나 인스타가 4:5를 더 우선 노출)
- **슬라이드당 텍스트**: 전체 면적의 20% 이하
- **폰트 크기**: 최소 24pt (모바일 가독성)

이미지는 GPT Image 2로 슬라이드별로 생성한다. 사용자(이정훈)는 생성된 이미지에 텍스트(훅·핵심 문장)를 Canva 등에서 얹는다. 즉, **GPT Image 2 = 배경/일러스트 / Canva = 텍스트 오버레이**의 역할 분담이다.

---

## 6. 슬라이드 구조

### 6-1. A 템플릿 — 교육 카루셀 (8~10장)

```
1장: 훅 — 질문형 8~10단어 (피드 첫인상)
2~3장: 문제 정의 (러너 공감 상황 + 데이터 1개)
4~7장: 핵심 포인트 (포인트당 1장, 3줄 이내)
8장: 요약 — 실천 팁 3개 (제품 언급 없이)
9장: CTA — "저장 / 공유 / 프로필 링크"
10장: (선택) 출처/크레딧
```

### 6-2. B 템플릿 — 팁/리스트 카루셀 (5~7장)

```
1장: 훅 — 숫자형 제목 (예: "VO2max 높이는 5가지 훈련법")
2~6장: 팁당 1장 (번호 + 핵심 문장 + 보조 설명 1줄)
7장: CTA + 저장 유도
```

## 7. 슬라이드별 텍스트 + 이미지 명세 분리

카루셀은 N장 전부에 이미지가 있어야 하므로, 본문 출력 시 **슬라이드 텍스트 영역**과 **이미지 명세 영역**을 분리한다. 슬라이드 텍스트만 보면 카루셀 흐름을 빠르게 검토할 수 있고, 이미지 작업할 때는 명세 영역만 보면 된다. 다른 채널(Journal/네이버)의 마커+명세 분리 방식과 일관성을 유지한다.

### 7-1. 슬라이드 텍스트 영역 — 본문 상단

본문 상단에 슬라이드 1~N의 텍스트만 모아 출력한다. 사용자(이정훈)가 Canva에 붙여넣을 카피 영역이다.

```markdown
## 슬라이드 텍스트

### SLIDE 1 / 9 — 훅
"마라톤 30km, 왜 거기서 무너질까?"

### SLIDE 2 / 9 — 문제 정의
"훈련은 충분했다. 그런데도 30km에서 다리가 멈춘다."

### SLIDE 3 / 9 — 데이터
"러너 56%가 30km 이후 페이스 30초 이상 드롭"

### SLIDE 4 / 9 — 핵심 포인트 1
"체내 글리코겐 약 2,000kcal"

### SLIDE 5 / 9 — 핵심 포인트 2
"풀마라톤 소모 약 2,800kcal"

### SLIDE 6 / 9 — 핵심 포인트 3
"800kcal가 모자란다"

### SLIDE 7 / 9 — 핵심 포인트 4
"부족분은 지방이 메워야 한다"

### SLIDE 8 / 9 — 요약
"무너지지 않으려면: 존2 훈련으로 지방 산화 능력을 키운다"

### SLIDE 9 / 9 — CTA
"이 카루셀이 도움이 됐다면 저장 + 공유"
```

### 7-2. 이미지 명세 영역 — 본문 하단

슬라이드 텍스트 영역 다음에 IMG 명세 섹션을 배치한다. 슬라이드 1~N과 1:1 매칭된다.

```markdown
---

## 이미지 명세

> GPT Image 2로 슬라이드별 배경 이미지 생성. 텍스트는 Canva에서 별도 작업.
> 모든 프롬프트에 §7-4 시리즈 일관성 공통 블록 포함.

### IMG-1 — SLIDE 1 훅 배경

- 종류: 분위기 사진
- 텍스트 공간: 상단 1/3 비워둠
- 비율: 4:5 (1080×1350px)
- alt 텍스트: "마라톤 30km 표지판을 지나는 러너"

**프롬프트 (GPT Image 2)**:
> A cinematic editorial photograph of a Korean male runner
> in his late 30s, lean build, viewed from behind as he passes
> the '30km' marathon course marker at early dawn.
> Composition: runner positioned in lower third, leaving the
> upper two-thirds of the frame as empty sky for text overlay.
> [공통 블록 — §7-4 참조]
> 4:5 aspect ratio.

---

### IMG-2 — SLIDE 2 문제 정의 배경
...
```

### 7-3. 텍스트 + 명세 매칭 규칙

- 슬라이드 N개 = 명세 N개. 1:1 매칭.
- 명세 헤더에 어느 슬라이드의 배경인지 명시 (`### IMG-1 — SLIDE 1 훅 배경`)
- 명세에 **텍스트 공간 위치**를 반드시 명시 (상단 1/3 / 하단 1/3 / 중앙 / 우측 절반 등)
- 출력 전 슬라이드 번호와 명세 번호의 1:1 일치 확인

### 7-4. 이미지 프롬프트 작성 원칙 — 카루셀 특수

카루셀 이미지는 다른 채널과 달리 **위에 텍스트가 얹히는 배경**이다. 따라서 다음을 반드시 프롬프트에 명시한다.

- **텍스트 공간 확보**: "Leave the upper third / lower third / center empty for text overlay" 같은 지시 필수
- **저채도·플랫**: 텍스트가 잘 보이도록. 화려한 배경은 금기
- **단순한 구도**: 인물 한 명, 풍경 한 장면 등. 복잡한 구도는 텍스트와 충돌
- **시리즈 일관성**: 같은 카루셀 안의 모든 슬라이드는 같은 색감·톤. 1장과 9장이 따로 놀면 안 됨

#### 시리즈 일관성 공통 블록

모든 슬라이드의 프롬프트 끝에 다음 블록을 반복해서 붙인다.

```
"Cool blue-grey color grade with desaturated highlights.
Editorial magazine aesthetic, similar to Magazine B.
Off-white (#FAFAF7) accents, deep navy (#1A2B3C) shadows,
warm orange (#E8743C) as occasional accent. Korean editorial
photography style. No text in image — leave space for
text overlay. 4:5 aspect ratio."
```

이 공통 블록을 슬라이드별 고유 묘사 뒤에 붙이면 시리즈 일관성이 유지된다.

### 7-5. 슬라이드 종류별 이미지 패턴

**훅 슬라이드 (1장)**
- 강한 단일 이미지 (러너 클로즈업, 30km 표지판, 새벽 코스 등)
- 텍스트 공간: 상단 1/3 또는 하단 1/3
- 색감: 가장 강한 임팩트 (cool blue-grey, 콘트라스트 ↑)

**문제 정의 슬라이드 (2~3장)**
- 데이터 시각화 또는 인물 장면
- 텍스트 공간: 우측 절반 또는 하단 1/3

**핵심 포인트 슬라이드 (4~7장)**
- 다이어그램 / 인포그래픽 / 인물 액션 컷 혼합
- 모든 슬라이드의 색감·구성 원칙이 동일하게 유지되어야 함
- 텍스트 공간: 중앙 또는 상단 1/3

**요약/CTA 슬라이드 (마지막)**
- 단순한 그래픽 또는 분위기 사진
- 텍스트 공간: 중앙 (텍스트가 메인)
- 색감: 가장 차분하게 (확신을 주는 톤)

```

권장: 주제 키워드 해시태그 5~10개

```

## 9. 네이버 클러스터 → 카루셀 원자화

### 9-1. 1:1 또는 1:2 매핑

네이버 클러스터 한 편에서 카루셀 1~2개가 도출된다.

| 매핑 | 적용 시점 | 구성 |
|------|---------|------|
| 1:1 | 기본 | 클러스터의 핵심 메시지 한 카루셀로 압축 (A 또는 B 템플릿) |
| 1:2 | 클러스터의 메시지가 풍부할 때 | 메커니즘 카루셀 (A) + 실천 팁 카루셀 (B) |

Pillar 글에서는 1:2~1:3 매핑이 가능하다 — 메커니즘 + 실천 팁 + (선택) FAQ 카루셀.

### 9-2. 원본 추적 (필수)

카루셀 초안 상단에 원본 네이버 글을 명시한다.

```
원본: [네이버 클러스터 제목]
출처 Journal: №01-A H2-1 (해당하는 경우)
```

### 9-3. 원자화 원칙

- 카루셀에서 "What"은 완전 공개 — 핵심 사실은 다 보여준다
- "How"는 80% 공개 — 핵심 방법론은 다루되 디테일은 일부 남긴다
- "Why(과학적 근거 심화)"는 티저만 → 블로그에서 전문 해설

이 원칙이 카루셀 → 블로그 트래픽 유도의 동력이 된다. 카루셀에서 다 보여주면 블로그를 안 본다.

## 10. 네이버 검색 유도 CTA (선택적)

프로필 링크 또는 캡션에서:

- "더 깊은 과학 해설이 궁금하다면 → 네이버에서 '[키워드]' 검색"
- 단, 해당 키워드로 네이버 상위 노출이 확인된 경우에만 사용
- SEO 직접 효과는 미입증 — 브랜드 인지 목적으로만 활용

## 11. 5중 셀프체크

### 11-1. 규격 체크 (5항목)

- [ ] 슬라이드 수: A 템플릿 8~10장 / B 템플릿 5~7장
- [ ] 비율 4:5 (1080×1350px) 명시
- [ ] 슬라이드당 텍스트 20% 이하
- [ ] 폰트 24pt 이상 (사용자 디자인 단계 가이드)
- [ ] 슬라이드 텍스트 영역과 이미지 명세 영역이 1:1 매칭, 슬라이드 N개 = 명세 N개

### 11-2. 규제 체크 (5항목)

- [ ] 슬라이드 텍스트에 "옥타코사놀", "지구력코어" 0회
- [ ] 이미지 프롬프트에 "옥타코사놀", "지구력코어" 0회 (생성 이미지 안에 박힐 위험)
- [ ] 5대 금지어 + 의약품 오인 용어 0회 (텍스트 + 프롬프트 + 캡션)
- [ ] 해시태그에 금지 태그 0건
- [ ] CTA가 제품 구매가 아닌 저장/공유/검색 유도

### 11-3. 원본 추적 체크 (3항목)

- [ ] 원본 네이버 클러스터 제목 명시
- [ ] 출처 Journal 명시 (해당하는 경우)
- [ ] 원본의 퍼널 단계와 카루셀 규칙 일치 (TOFU 원본 → TOFU 카루셀)

### 11-4. One Message 체크 (4항목)

- [ ] 1장 훅이 핵심 메시지의 질문형
- [ ] 중간 슬라이드의 근거가 3개 이하
- [ ] 마지막 장이 한 줄 단언으로 닫힘
- [ ] "이 카루셀이 남기는 한 문장"이 명확

### 11-5. 이미지 체크 (5항목)

- [ ] 모든 슬라이드(N장)에 이미지 명세 1:1 매칭 — IMG-1 ↔ SLIDE 1, IMG-N ↔ SLIDE N
- [ ] 모든 프롬프트에 텍스트 공간 확보 지시 (Leave space for text overlay)
- [ ] 시리즈 일관성 공통 블록(§7-4) 모든 슬라이드 적용
- [ ] 컬러 팔레트(`#FAFAF7` / `#1A2B3C` / `#E8743C`) 일관 적용
- [ ] 슬라이드 종류별 이미지 패턴(§7-5) 적합성 확인

## 12. 작업 흐름

사용자 요청: `[네이버 클러스터 제목]을 카루셀로 변환해줘`

**설계**
1. 원본 네이버 클러스터 글 확인
2. One Message 1문장으로 정리
3. 1:1 또는 1:2 매핑 결정 (Pillar는 1:2~1:3)
4. A 또는 B 템플릿 선택
5. 슬라이드 수 확정 + 각 슬라이드 역할 매핑

**작성**
6. 슬라이드 텍스트 영역 작성 (1장 훅 → 중간 슬라이드 → 마지막 장)
7. 이미지 명세 영역 작성 (IMG-1부터 IMG-N까지 슬라이드와 1:1 매칭)
8. 시리즈 일관성 공통 블록(§7-4) 모든 명세에 포함
9. 캡션 작성 (훅 + 3줄 요약 + CTA + 해시태그)

**검수**
10. 5중 셀프체크 실행 (총 22항목) + 슬라이드↔명세 1:1 매칭 검증
11. 실패 항목이 있으면 출력 전 사용자에게 보고
12. .md 파일 출력 — 슬라이드 텍스트 영역 / 이미지 명세 영역 / 캡션 / 해시태그

## 13. 출력 형식

```yaml
---
title: "[카루셀 제목]"
channel: instagram_carousel
funnel_stage: TOFU
template: A | B
source_blog: "[네이버 클러스터 제목]"
journal_source: "Journal №01-A" | "독립"
slide_count: 8 | 9 | 10 (A) | 5 | 6 | 7 (B)
image_count: (slide_count와 동일 — 슬라이드 1장당 이미지 1개)
review_required: N
review_note: "TOFU 규칙 동일 적용 — 제품명·성분명 0회 (텍스트+프롬프트+캡션)"
date_drafted: YYYY-MM-DD
---
```

본문 구조:
1. 카루셀 제목 + 원본 정보
2. **슬라이드 텍스트 영역** — SLIDE 1 / N부터 SLIDE N / N까지 텍스트만 모음
3. **이미지 명세 영역** — IMG-1부터 IMG-N까지 슬라이드와 1:1 매칭, 프롬프트 + 메타정보
4. 캡션 텍스트
5. 해시태그 목록
6. (선택) 디자인 참고 메모
