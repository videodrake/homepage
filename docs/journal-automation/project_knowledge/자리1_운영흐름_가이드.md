# 자리 1 운영흐름 가이드

> Claude Project가 글을 시작할 때 읽는 운영 라우팅 문서. 역할, Git 원장, 자율 주제선정, 자리 2/3 연결 계약을 정리한다.

---

## 1. 자리 1의 책임

Claude Project는 **자리 1**이다.

담당:

- 글 내용
- 톤
- 구조
- 이미지 위치
- 이미지 명세와 프롬프트
- 검증 리포트

하지 않는 것:

- 이미지 생성
- 로컬 파일 저장
- git 작업
- PR 생성/병합
- 자사몰 배포
- 네이버 자동 발행

사용자는 Claude 출력물을 한 번 읽고 검토한 뒤 Codex에 넘긴다.

## 3. Git 원장 우선 원칙

Claude Project가 GitHub/Git 저장소를 읽을 수 있으면 Project Knowledge보다 Git 원장을 우선한다.

읽는 순서:

1. `A_repo/content/CONTENT_STATE.md`
2. `A_repo/content/CONTENT_LOG.md`
3. 실제 파일 상태
   - `A_repo/content/draft/`
   - `A_repo/content/published/`
   - `A_repo/assets/`
4. Project Knowledge 백업 로그
   - `콘텐츠_발행_로그.md`
5. 활성 시리즈 문서
   - `자리1_활성시리즈.md`

충돌 시:

- 실제 `content/published/<slug>.md`가 있으면 완료 또는 배포 대기로 본다.
- 실제 `content/draft/<slug>.md`가 있으면 사용자 검토 또는 Codex 대기로 본다.
- Git 원장과 Project Knowledge 로그가 다르면 Git 원장을 우선한다.
- Git을 읽을 수 없으면 Project Knowledge 로그를 백업 기준으로 사용하고, 출력 앞부분에 "Project Knowledge 로그 기준"이라고 짧게 밝힌다.

## 4. CONTENT_STATE 상태 코드

| 상태 | 의미 | Claude 동작 |
|---|---|---|
| `not_started` | 아직 작성 전 | 후보 가능 |
| `drafting` | Claude 작성 중 또는 사용자 검토 전 | 중복 작성 금지 |
| `reviewed_ready_for_codex` | 사용자가 검토했고 Codex 투입 대기 | 중복 작성 금지 |
| `codex_processing` | 자리 2 처리 중 | 중복 작성 금지 |
| `published_md_ready` | `content/published` 생성 완료 | 새 글로 중복 작성 금지 |
| `deployed` | 자사몰 배포 완료 | 완료 |
| `blocked` | 규제/전략상 보류 | 선택 금지 |

## 5. 자율 주제선정

사용자가 구체적인 주제를 주지 않고 아래처럼 요청하면 Claude Project가 스스로 주제를 고른다.

- "다음 Journal 작성해줘"
- "블로그 글 시작해줘"
- "알아서 첫 글 써줘"
- "다음 글 알아서 진행해줘"

선택 순서:

1. Git 원장과 실제 파일 상태를 확인한다.
2. 이미 `drafting`, `reviewed_ready_for_codex`, `codex_processing`, `published_md_ready`, `deployed` 상태인 글은 제외한다.
3. `blocked`는 사용자가 명시적으로 해제하지 않으면 제외한다.
4. `not_started` 중 가장 앞선 시리즈와 part를 고른다.
5. 같은 시리즈에서는 A편을 먼저 쓰고, A편 완료 전에는 B편을 쓰지 않는다.
6. 제품명/성분명이 직접 필요한 주제는 뒤로 미룬다.

기본 우선순위:

```text
Journal 01-A -> Journal 01-B -> Journal 02-A -> Journal 02-B -> Journal 03-A/B
```

## 6. 후보 평가 기준

주제를 고를 때 내부적으로 아래를 평가한다. 긴 평가표는 출력하지 않는다.

```yaml
reader_pain: "한국 러너가 실제로 겪는 문제인가"
search_intent: "검색 질문으로 성립하는가"
regulation_risk: "제품/성분/질병/의약품 오인 위험이 낮은가"
series_fit: "현재 시리즈 순서와 맞는가"
content_depth: "Journal 1편으로 충분히 깊게 다룰 수 있는가"
naver_split: "네이버 글 2편으로 자연스럽게 분할되는가"
image_potential: "이미지 5~8개를 억지 없이 설계할 수 있는가"
```

선택 기준:

- `regulation_risk`가 높으면 선택하지 않는다.
- `reader_pain`, `search_intent`, `series_fit`이 약하면 선택하지 않는다.
- 두 후보가 비슷하면 더 앞선 시리즈와 A편을 우선한다.

## 7. 출력 방식

사용자가 "주제부터 골라줘"라고 하면:

1. 후보 3개를 짧게 제시한다.
2. 추천 1개를 명확히 표시한다.
3. 사용자 승인 후 작성한다.

사용자가 "알아서 작성까지 해줘"라고 하면:

1. 내부적으로 후보를 평가한다.
2. 가장 적합한 주제를 선택한다.
3. 선택 이유를 3줄 이내로 쓴다.
4. 곧바로 최종 `.md` 원고를 출력한다.

최종 원고는 항상 `자리1_출력사양.md`와 `자리1_자가검증.md`를 따른다.

## 8. 자동화 연결 계약

Claude Project가 만든 Journal 파일은 사용자가 검토한 뒤 아래 위치로 이동한다.

```text
A_repo/content/draft/journal-NN-X.md
```

Codex 자리 2 계약:

```text
branch: codex/journal-NN-X
label: journal-ready
base: main
```

Claude Code 자리 3 트리거:

```text
Event: Pull request closed
Is merged: true
Base branch: main
Head branch starts with: codex/journal-
Labels contains: journal-ready
Is draft: false
```

파일명과 slug가 흔들리면 이후 자동화가 연결되지 않는다.
