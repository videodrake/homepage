# Step 2 하네스 프롬프트 - Journal A에서 네이버 클러스터 2편 생성

아래 입력값과 Journal A 원문을 바탕으로 네이버 TOFU 클러스터 글 2편을 작성하라.  
두 글은 같은 Journal A에서 파생된 자매 클러스터이며, 구조와 검증 리포트가 동일해야 한다.

중요: 네이버는 자동 발행 대상이 아니다. 이 프롬프트는 수동 발행용 원고를 만드는 데만 사용한다. Codex 자리 2와 Claude Code 자리 3 자동화는 자사몰 Journal 파일(`journal-...md`)에만 적용된다.

## 입력값

```yaml
series_no: "01"
source_journal: "Journal №01-A"
source_slug: "journal-01-a"
cluster_count: 2
cluster_1:
  source_h2: "H2-1"
  working_title: "마라톤 30km에서 다리가 멈추는 이유 - 800kcal 부족분 계산"
  slug: "naver-01-a-1"
  primary_keyword: "마라톤 30km 벽"
  secondary_keywords:
    - "글리코겐 고갈"
    - "마라톤 후반 페이스"
cluster_2:
  source_h2: "H2-2"
  working_title: "글리코겐과 지방, 러너 몸은 둘을 어떻게 나눠 쓰나"
  slug: "naver-01-a-2"
  primary_keyword: "글리코겐 지방"
  secondary_keywords:
    - "에너지 시스템"
    - "마라톤 연료"
published_sibling_links:
  - "아직 없음"
source_text: |
  여기에 Journal №01-A 원문 전체를 붙여넣는다.
```

## 반드시 참조할 Project Knowledge

- `운영_룰북/mode_tofu.md`
- `운영_룰북/이미지_가이드.md`
- `운영_룰북/발행_매핑_가이드.md`
- `운영_룰북/콘텐츠_발행_로그.md`
- `운영_룰북/규제_핵심요약_치트시트.md`
- `자리1_콘텐츠품질_가이드.md`

## 작업 순서

1. Journal A 원문에서 H2-1과 H2-2의 핵심 주장, 수치, 비교표, FAQ 후보를 분리한다.
2. 각 H2를 네이버 TOFU 글 1편으로 변환한다. 단순 요약이 아니라 검색 유입자가 바로 이해할 수 있게 다시 쓴다.
3. 각 글은 질문형 또는 키워드 포함형 제목을 사용한다.
4. 각 글 첫 두 문장 안에 타겟 키워드와 직접 답변을 넣는다.
5. 각 글은 이미지 마커 8~13개를 가진다.
6. 각 글 끝에 `## 이미지 명세`를 만들고 마커와 1:1로 맞춘다.
7. 각 글 끝에 자매 클러스터 내부링크 섹션을 둔다. 아직 발행되지 않은 글은 `[내부링크 예정: 제목]`으로 표기한다.
8. 각 글 끝에 `## 검증 리포트`를 붙인다.
9. 첫 300~500자는 검색어 설명이 아니라 실제 러너가 겪는 장면으로 시작한다.
10. SEO/AEO는 타겟 키워드 반복이 아니라 직접 답변, H2, 비교표, FAQ, alt 텍스트로 구현한다.
11. AI처럼 균일한 문단 리듬을 피하고, 실제 러너의 흔한 상황을 최소 2개 반영한다.
12. 검증하기 어려운 논문명, 질환, 통증 진단, 개인별 처방 주제는 피한다.
13. 각 H2 첫 문단은 그 섹션의 결론을 먼저 말한다.
14. 출처 없는 "연구에 따르면" 표현을 쓰지 않는다.
15. 한국 30~40대 러너가 바로 알아볼 생활/대회 맥락을 최소 2개 넣는다. 예: 새벽 대회장, 물품보관소, 화장실 줄, 출발 그룹 대기, 한강/잠실/여의도/상암/광화문 러닝 장면, 러닝크루 단체 채팅방, Garmin/Strava 기록 확인, 카카오톡 기록 캡처 공유.
16. 독자를 탓하거나 혼내지 않는다. "의지가 약해서"가 아니라 "몸 안의 계산이 달라지는 구간"으로 설명한다.
17. 과한 응원, 썸네일식 과장, 친한 척하는 구어체를 피한다. 네이버 톤이라도 "꿀팁", "아직도 이렇게 뛰나요?" 같은 표현은 쓰지 않는다.
18. 최종 출력 전 유용성, 신뢰, 웹 독해, 한국 독자 감성, AI스러움 제거 순서로 5회 편집한다.

## 균일화 규칙

- 두 글의 섹션 순서는 같게 유지한다.
- 두 글의 검증 리포트 항목은 같은 순서로 출력한다.
- 각 글은 독립 발행 가능해야 하며, 다른 글을 읽어야만 이해되는 표현을 쓰지 않는다.
- Journal 문장을 그대로 복붙하지 말고 네이버 톤으로 재작성한다.
- 제목과 H2는 과장하지 않는다. 검색 질문에 답하는 문장으로 쓴다.
- 이 결과물은 `content/draft/` 자동화 투입물이 아니다. 사용자가 별도로 검토해 네이버에 수동 발행한다.

## 실패 조건

아래 중 하나라도 발생하면 최종 출력 전에 스스로 수정하라.

- 제품명, 성분명, 자사몰, 구매, 추천, 보충제 유도 표현이 나온다.
- 이미지 명세가 본문 마커보다 적거나 많다.
- `alt 텍스트`에 타겟 키워드가 자연스럽게 들어가지 않는다.
- 내부링크가 MOFU, 제품 페이지, 자사몰로 향한다.
- 두 글의 형식이 서로 다르다.
